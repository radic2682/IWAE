# 작업 공간 2: 세션 · 화면 · 칸 (tmux 식)

상태: 구현됨 (2026-11-12, 미릴리스).
조작용 예시: https://claude.ai/artifact/E45T2rtzccw4G1dR1RJMfF (비공개 링크)
앞 설계: [workspace-channels.md](workspace-channels.md). 탭, 색 채널, 가리키기 신호, 연결선은 그대로 쓰고, 그 위에 칸 구조를 tmux 처럼 바꾼다.

## 1. 왜

[workspace-channels.md](workspace-channels.md) 의 다섯 단계(로컬 main, 미릴리스)로 노트가 일반 탭이 되었고 칸끼리 색으로 연동된다. 남은 한계는 세 가지다.

- **칸 배치가 정해진 10가지(`src/core/pdfSplit.ts`)이고 최대 4칸이다.** 노트가 칸을 하나 차지하므로 문서 칸이 금방 모자란다.
- **한 앱 창에는 배치가 하나뿐이다.** "읽기용 배치"와 "정리용 배치"를 오가려면 매번 다시 짜야 한다.
- **설정을 이름 붙여 저장하고 다시 열 수 없다.** 세션은 `session.json` 하나에 자동으로 저장될 뿐이다.

사용자는 tmux 를 쓰는 방식 그대로를 원한다. 칸마다 독립적인 탭을 가진 창이 있고, 그 묶음을 저장해 두고 쓰고, 여러 앱 창을 띄우고, tmux 명령어로 조작하는 방식이다.

## 2. 용어

```
Vault
 └ 세션        이름 붙여 저장·불러오기 (예: 「논문 3장」, 「발표 준비」)
    └ 화면     칸을 모은 파티션 = tmux window (맨 위 줄: 0 읽기 · 1 비교 · 2 정리)
       ├ 칸    탭이 있는 창 = tmux pane (자기 탭 줄 · 도구줄 · 색 채널)
       │  └ 탭 PDF · MD · 노트 · 캔버스 · 번역기 · (나중에) 터미널, git 이력
       └ 떠 있는 칸   칸과 같지만 위에 뜬다 (화면 전체 또는 특정 칸에 붙음)
앱 창 = tmux client. 세션에 붙어서 그 세션의 화면 하나를 보여 준다.
```

- UI 에서는 **세션 / 화면 / 칸 / 떠 있는 칸 / 앱 창**이라고 부른다. "창"은 앱 창(OS 창)과 헷갈리므로 칸에 쓰지 않는다.
- tmux 명령 이름(`new-window`, `split-window`)은 영어 그대로 둔다. tmux 를 아는 사람이 바로 쓰게 하기 위해서다.
- 앱 창을 하나 더 띄운다고 세션이 새로 생기지 않는다.
  - 같은 세션에 두 앱 창이 붙어 각자 다른 화면을 보여 줄 수 있다. 예: 모니터 둘에 0 번과 1 번 화면.
  - 다른 세션을 다른 앱 창에 띄울 수도 있다. 이때는 서로 연동하지 않는다.

## 3. 화면 구성

```
┌ 맨 위 줄 ─────────────────────────────────────────────────────────────┐
│ ☰ ◧ │ 논문 3장 ▾ │ 0 읽기 │ 1 비교 │ 2 정리 │ ＋ │      ⌘ 명령 (Ctrl+K)  – □ × │
├───────────────────────────────────────────────────────────────────────┤
│ ┌ 칸 0 ──────────────────────┐ ┌ 칸 1 ───────────────────────────┐   │
│ │ ● 0 │ 논문.pdf │ 설명서.pdf ⋯│ │ ● 1 │ 노트 A ⋯                  │   │
│ │ ✋ I ▭ 🖍 …        3/12 109% │ │ 본문 B I U …           🔍 ＋     │   │
│ │           (PDF)            │ │            (노트)  ┌ 떠 있는 칸 ┐ │   │
│ └────────────────────────────┘ └────────────────────│ 번역기     │─┘   │
├ 아래 상태 줄 ──────────────────────────────────────────────────────────┤
│ [논문 3장] 0:읽기* 1:비교- 2:정리      (알림 · 명령줄)        접두키  ?  │
└───────────────────────────────────────────────────────────────────────┘
```

- **맨 위 줄:** 앱 메뉴, 왼쪽 바, **세션 이름 ▾**(목록 · 새로 · 저장 · 이름 바꾸기 · 앱 창으로 띄우기), **화면 탭**(누르기 · 끌어 순서 · 접두키 + 숫자), 명령(Ctrl+K), 창 단추가 있다.
  - 지금 맨 위 줄에 있는 문서 탭 영역(칸마다 위쪽에 놓이던 탭 줄)과 「창 나누기」 · 「옆에 노트」 단추는 빠진다.
- **칸 머리:** 색 점, 칸 번호, 탭 줄(보는 탭은 안 줄임, 넘치면 「+N」, 미리보기 탭), ⋯ 메뉴가 있다.
  - ⋯ 메뉴: 오른쪽으로 나누기 · 아래로 나누기 · 띄우기 · 크게 · 새 화면으로 떼기 · 색 · 닫기.
  - 모든 칸이 같다. 지금처럼 "아랫줄 칸만 칸 안에 탭 줄" 같은 예외가 없다.
- **칸 도구줄:** 보이는 탭의 종류에 따라 바뀐다(PDF 도구 · 노트 서식 · MD 편집 · 캔버스 도구 · 번역 언어 줄). 지금의 칸별 도구줄(`PaneToolbar`)을 그대로 쓴다.
- **아래 상태 줄:** tmux 처럼 `[세션] 0:읽기* 1:비교-` 가 보이고, 짧은 알림(AI 가 보는 중, 저장됨)과 `:` 명령줄이 같은 자리를 쓴다.
  - 설정에서 끌 수 있다. 끄면 접두키를 누를 때만 잠깐 나타난다.
  - 지금 오른쪽 아래에 뜨는 알림 줄기는 상태 줄이 켜져 있을 때 상태 줄로 옮긴다.

## 4. 칸 나누기 트리

`PdfSplitLayoutId`(10가지) + `PaneId = 'left' | 'right' | 'third' | 'fourth'` 를 **나누기 트리**로 바꾼다.

```ts
type LayoutNode =
  | { readonly kind: 'pane'; readonly paneId: string }
  | { readonly kind: 'split'; readonly id: string; readonly dir: 'h' | 'v'; readonly ratio: number; readonly a: LayoutNode; readonly b: LayoutNode }
interface Pane { readonly id: string; readonly tabs: TabsState; readonly channel: Channel | null }
interface Screen { readonly id: string; readonly name: string; readonly root: LayoutNode; readonly floats: readonly FloatingPane[]; readonly zoomed: string | null }
```

- 칸 id 는 고정 이름 대신 만들 때 붙이는 문자열이다. 칸 번호(0, 1, 2…)는 트리를 왼쪽 위부터 차례로 센 값이며 저장하지 않는다.
- 상한은 화면당 8 칸이다. 칸 최소 크기는 240×160px 이고, 더 나누면 「칸이 너무 작습니다」로 막는다.
- 나누기: `split-window -h` 는 지금 칸을 좌우로, `-v` 는 위아래로 나눈다. 새 칸은 지금 칸의 색을 받는다.
  - 새 칸은 비어 있고 「PDF · MD · 노트 · 캔버스 · 번역기」 빠른 단추를 보인다.
- 경계선을 끌어 `ratio` 를 바꾼다. 지금 구분선 끌기(`SplitPanes`)를 트리용으로 일반화한다.
- 탭 끌어 붙이기(`src/app/tabDock.ts`)는 "대상 칸을 그 방향으로 나누고 새 칸에 탭을 넣기"로 일반화한다.
  - 정해진 배치 사이를 바꾸는 `dockSplit` 표는 없어진다.
- `select-layout even-horizontal | even-vertical | main-vertical | main-horizontal | tiled` 는 칸 순서를 지키며 트리를 다시 짠다.
- 연결선(`src/app/workspaceLinks.ts`)은 이미 DOM 위치로 이웃을 판단하므로 트리에서도 그대로 동작한다.
- 지금의 배치 프리셋(「읽기」 · 「노트 왼쪽」 · 「비교」 · 「정리」)은 **화면 템플릿**이 된다. 「새 화면 ▸ 읽기」로 그 모양의 화면을 만든다.

## 5. 떠 있는 칸

- 어떤 탭이든 칸에서 꺼내 띄울 수 있다(`float-pane`, 칸 ⋯ 「띄우기」). 떠 있는 칸은 보통 칸과 같은 `Pane` 이고, 탭 줄 · 도구줄 · 색 채널을 가진다.
- 붙는 곳은 둘 중 하나다.
  - **화면 전체:** 화면 위 어디든.
  - **특정 칸:** 그 칸 안에서 그 칸을 따라 움직이고, 칸이 닫히면 화면으로 옮긴다. 지금 번역기 창이 이 방식이다.
- 조작: 머리 끌기로 옮기기, 오른쪽 아래 모서리로 크기, 「▁」 접기(머리만 남김), 「⇲」 칸으로 넣기(`embed-pane`), 모두 숨기기·보이기(접두키 + `f`).
- `display-popup` 은 떠 있는 번역기를 새로 띄운다. 나중에 터미널이 생기면 tmux 처럼 떠 있는 터미널을 띄운다.
- 연결선: 떠 있는 칸이 문서 칸과 겹치면 선을 그리지 않고 카드 강조만 한다. 겹치지 않으면 짧은 선을 그린다.
- 지금의 떠 있는 번역기(`src/app/TranslatorPanel.tsx`, `translatorPanelState.ts`)는 "번역기 탭을 담은 떠 있는 칸"으로 옮긴다. 위치와 크기 저장은 세션으로 간다.

## 6. 세션

- **저장되는 것:** 화면들(이름, 순서, 트리, 비율), 칸마다 탭 · 보는 탭 · 미리보기 · 색 채널, 떠 있는 칸의 위치 · 크기 · 접힘, 문서별 스크롤 위치와 배율, 마지막으로 만진 노트.
- **어디에:** Vault 안 `.iwae/sessions/<이름>.json`.
  - Vault 를 다른 PC 로 옮기면 세션도 따라간다. 앱 창 크기와 모니터 위치처럼 PC 마다 다른 것은 앱 데이터에 따로 둔다.
  - 지금 `session.json`(`src/core/session.ts`)은 첫 실행 때 「기본」 세션으로 옮긴다.
- **자동 저장:** 지금처럼 바뀔 때마다 조용히 저장한다. 「세션 저장」은 이름을 새로 붙여 갈래를 만드는 동작(`save-session 이름`)이다.
- **바꾸기:** 세션 목록(접두키 + `s`, 세션 이름 ▾, `switch-client -t 이름`)에서 고른다. 이 앱 창이 그 세션의 마지막 화면으로 넘어간다. 앱을 켜면 마지막 세션으로 시작한다.

## 7. 앱 창

- 앱 창은 `{ 세션, 보는 화면 }` 을 가진다. 「앱 창으로 띄우기」(`new-client`)는 같은 세션에 붙은 새 앱 창을 연다. 다른 세션을 고를 수도 있다.
- **한 세션에 앱 창이 여럿 붙으면** 세션 상태를 한 곳(Rust 쪽 세션 저장소)이 가지고, 바뀔 때마다 이벤트로 모든 앱 창에 알린다.
  - 지금 "새 창(Ctrl+Shift+N)"은 같은 Vault 를 보는 독립 창이고 노트 저장만 합친다. 이것을 "세션에 붙은 앱 창"으로 바꾼다.
- **색 채널은 같은 세션 안이면 앱 창을 넘어 이어진다.** 가리키기 신호(`src/app/workspaceSignal.ts`)를 앱 창 사이 이벤트로 넓힌다. 예: 모니터 A 의 PDF 형광펜을 누르면 모니터 B 의 노트가 그 카드로 간다.
- 연결선은 앱 창 안에서만 그린다. 앱 창을 넘는 연결은 카드 강조와 「→ 문서」 링크로 보인다.
- `detach`(접두키 + `d`)는 이 앱 창만 닫는다. 세션은 남는다. 마지막 앱 창을 닫으면 앱이 끝난다.
- **같은 화면을 두 앱 창이 동시에 보면** tmux 처럼 같은 화면을 보여 준다. 칸 포커스와 스크롤은 앱 창마다 따로 둔다.

## 8. 키와 명령

### 8.1 접두키

- 기본값은 **`Ctrl+B`**(tmux 기본)이다. 사용자가 tmux 와 같기를 원했고(처음에는 `Ctrl+Space` 로 했다가 바꿨다), 겹치는 메모 편집기의 굵게는 접두키를 한 번 더 누르는 send-prefix(`Ctrl+B Ctrl+B`)로 보낸다.
  - 설정에서 `Ctrl+B`(기본(tmux)) · `Ctrl+Space` · `Ctrl+A` · 직접 지정으로 바꿀 수 있다. 직접 고른 접두키는 그대로 남고 기본값만 바뀐다. `Ctrl+A` 를 고르면 전체 선택이 `Ctrl+A Ctrl+A` 가 된다.
  - 한국어 Windows 에서 `Ctrl+Space` 가 입력기 전환에 걸려 있는 PC 도 있어 기본으로 두지 않았다. 처음 실행(접두키를 고른 적이 없는 첫 실행)에는 「접두키 고르기」 창이 한 번 떠서 고르게 한다(`PrefixKeyDialog`, 확인 · 나중에 모두 다시 묻지 않는다). `.iwae/keys.conf` 가 접두키를 정하면 창은 뜨지 않는다.
  - 화면의 접두키 힌트(상태 줄 칩, 키 목록, 칸 ⋯ 메뉴, 빈 칸)는 등록부 `prefixKey` 의 지금 키(`shortcutText`)를 읽는다.
- 접두키 다음 키는 **자판 위치(`KeyboardEvent.code`)로 읽는다.** 한글 입력 상태에서 `z` 가 `ㅋ` 로 오거나 Shift 조합(`%` · `"` · `!`)이 숫자로 오는 문제를 피한다. 조작용 예시에서 확인했다.
- 접두키는 편집기 안에서도 동작한다(tmux 와 같음). 접두키 다음 키는 편집기로 가지 않는다.

### 8.2 접두키 다음 키

| 키 | 동작 | 명령 |
| --- | --- | --- |
| `%` / `"` | 좌우 / 위아래로 나누기 | `split-window -h` / `-v` |
| `←` `↑` `→` `↓` · `o` | 칸 이동 · 다음 칸 | `select-pane -L/-U/-R/-D` |
| `z` | 이 칸만 크게 / 되돌리기 | `resize-pane -Z` |
| `x` | 칸 닫기 | `kill-pane` |
| `!` | 칸을 새 화면으로 | `break-pane` |
| `{` `}` | 칸 자리 바꾸기 | `swap-pane -U/-D` |
| `Space` | 배치 돌리기 | `select-layout` (차례로) |
| `q` | 칸 번호 보이기, 숫자로 이동 | `display-panes` |
| `c` · `,` · `&` | 새 화면 · 화면 이름 · 화면 닫기 | `new-window` · `rename-window` · `kill-window` |
| `n` `p` `l` · `0`–`9` | 다음 · 이전 · 마지막 화면 · 번호로 | `next-window` … `select-window -t N` |
| `f` · `w` | 떠 있는 칸 숨기기·보이기 · 떠 있는 번역기 | `toggle-floating` · `display-popup` |
| `s` · `d` | 세션 목록 · 이 앱 창 떼기 | `choose-session` · `detach` |
| `:` · `?` | 명령줄 · 키 목록 | — · `list-keys` |

### 8.3 `:` 명령줄

- 아래 상태 줄에서 친다. 명령 팔레트(Ctrl+K)도 같은 명령을 받는다. `;` 로 여러 명령을 잇는다. tmux 줄임말(`splitw`, `neww`, `killp`, `selectl`…)을 받는다.
- **tmux 명령:**
  - `split-window [-h|-v]`, `select-pane [-L|-R|-U|-D|-t N]`, `resize-pane -Z`, `kill-pane`, `swap-pane`, `break-pane`, `join-pane -s N`
  - `new-window [-n 이름]`, `select-window -t N`, `next-window`, `previous-window`, `last-window`, `rename-window`, `kill-window`, `select-layout <이름>`
  - `new-session [이름]`, `switch-client -t 이름`, `rename-session`, `detach`, `list-keys`, `display-panes`, `display-popup`
- **IWAE 명령:**
  - `open <문서·노트 이름>`: 지금 칸에 탭으로 연다.
  - `set-channel blue|green|orange|none`
  - `float-pane`, `embed-pane`, `toggle-floating`
  - `save-session [이름]`, `new-client`: 같은 세션에 앱 창을 더한다.
- **설정 파일(나중):** `.iwae/keys.conf` 에 `bind-key` / `unbind-key` / `set prefix C-b` 를 tmux 문법으로 쓴다. 지금의 단축키 바꾸기 화면과 같은 저장소를 쓴다.
- **MCP:** 바깥 AI 가 같은 명령을 보내는 도구 하나(`workspace_command`)를 둔다. AI 가 "PDF 옆에 노트 열고 아래에 번역기 띄워" 를 명령 몇 줄로 할 수 있다. 지금 MCP 의 탭 · 배치 도구(`set_layout`, `open_note` …)는 이 명령 위에 다시 만든다.

| 맨 위 줄의 칸별 문서 탭 영역 | 칸 머리의 탭 줄. 맨 위 줄은 세션 · 화면 탭 |
| 배치 프리셋 4가지 | 화면 템플릿(「새 화면 ▸ 읽기」) |
| 「옆에 노트 열기」(Ctrl+Shift+M) | `split-window -h ; open <마지막 노트>` 로 정의된 기본 키 바인딩. 단추는 칸 ⋯ 메뉴로 |
| 떠 있는 번역기 창 | 번역기 탭을 담은 떠 있는 칸 |
| `session.json` 하나 | `.iwae/sessions/*.json` 여러 개, 첫 실행 때 「기본」으로 옮김 |
| 새 창(Ctrl+Shift+N) = 독립 창 | 세션에 붙는 앱 창, 색 채널이 앱 창을 넘음 |
| 오른쪽 아래 알림 줄기 | 상태 줄이 켜져 있으면 상태 줄로 |
| MCP 탭 · 배치 도구 | `workspace_command` + 기존 도구는 그 위에 |

그대로 쓰는 것: 탭 종류와 노트 탭(`MemoNoteTabView`), 색 채널과 가리키기 신호, 미리보기 탭, 연결선 층, 캔버스 연동.

## 12. 구현 메모

### 단계 1 (나누기 트리)

- **트리와 칸 상태.** 트리 모델과 도우미는 `src/core/layoutTree.ts`(잎 차례, 부모 찾기, 바꾸기, 빼기, 나누기, 비율, 자리 바꾸기, `relayout`, 칸 수 상한 8 · 최소 크기 240×160, 예전 배치 → 트리, 저장 읽기)에 있다. 칸 id 는 `newPaneId()` 가 이번 실행에서 한 번도 안 쓴 `p<번호>` 를 만든다. 칸 상태는 칸 id → 탭 줄(`PanesState`)과 칸 id → 색 채널(`PaneChannels`) **두 맵**으로 갖고, 트리(`LayoutNode`)와 함께 `useVault` 가 한 상태(`workspace`)로 들고 있다. 설계의 `Pane { tabs, channel }` 한 객체로 합치면 칸 상태를 읽는 모든 순수 함수를 다시 써야 해서 합치지 않았다. 세션에 저장할 때만 `paneState[칸 id] = { tabIds, activeId, channel }` 로 합친다.
- **그리기.** 칸을 트리 모양대로 중첩하지 않고, 칸 id 를 key 로 한 평평한 목록에 절대 위치(%)로 놓는다(`SplitPanes`). 나누기·닫기로 모양이 바뀌어도 남은 칸의 DOM(PDF 보기)이 다시 만들어지지 않는다. 경계선은 나누기마다 하나(`.pane-tree-divider`)이고, 끄는 동안은 `SplitPanes` 안에서만 비율을 다시 그리다 놓을 때 한 번 `onRootChange` 로 알린다. 두 쪽의 최소 크기(칸마다 240×160, 중첩이면 합)를 지킨다.
- **상단바 탭 줄.** 칸이 **하나일 때만** 그 칸의 탭 줄이 상단바에 있다(지금과 같은 모양을 지키려고). 칸이 둘 이상이면 모든 칸의 탭 줄이 칸 안 맨 위로 옮겨 간다(`.pane-grid-tabs`, 지금 격자 배치 아랫줄 칸과 같은 껍질). 상단바 구역을 임의의 트리에 맞추는 일(`gridTopZones` 등)은 없앴다. 단계 2 에서 한 칸일 때도 칸 머리로 옮긴다.
- **「창 나누기」 목록.** 예전 아홉 배치(`PdfSplitLayoutId`)를 같은 모양의 트리로 지금 칸에 적용한다(`applyLegacyLayout`: 칸 차례를 이어 쓰고, 모자라면 빈 칸, 남으면 마지막 칸 뒤에 탭을 합친다). 단추 모양은 트리가 어느 배치와 같은 모양이면 그 배치, 아니면 「직접 나눈 배치」다. 단계 3 의 템플릿이 이 목록을 대신한다.
- **칸이 너무 작거나 8개일 때.** 탭을 가장자리에 놓기, 옆에 노트 열기, 신호가 여는 새 칸은 `splitRefusal` 로 먼저 본다. 가장자리 놓기·칸 수 바꾸기는 「칸이 너무 작습니다」·「칸은 8개까지입니다」를 알리고, 옆에 노트 열기·신호는 알리지 않고 가장 오른쪽(노트) · 보낸 칸(문서)의 탭으로 간다(예전 「가득이면」 규칙). 칸 크기는 DOM 에서 재서(`paneSizeOf`), 잴 수 없으면(0) 크기는 따지지 않는다.
- **세션.** 새 필드 `layout`(트리)·`paneState`. 예전 세션은 읽을 때 `workspaceFromSession` 이 배치 id(예전엔 localStorage `iwae:pane-layout:v1`, 없으면 한 칸)와 `panes.left/right/third/fourth`·`paneChannels` 를 같은 모양의 트리로 옮긴다(보이지 않던 칸의 탭은 마지막 칸 뒤에 합친다). 떼어 낸 창·새 창은 늘 한 칸에서 시작한다. 예전 `panes`·`paneChannels` 는 읽기만 하고 다시 쓰지 않는다.
- **MCP.** `left/right/third/fourth` 는 칸 번호 0–3 으로, `'0'`–`'7'`(숫자도)·`active`·`other`·칸 id 를 받는다. 아직 없는 번호는 칸을 늘려 만든다. `app_state` 는 `panes: [{ index, id, channel, tabs, active_tab }]` 와 `layout: { pane_count, active_pane(번호), active_pane_id, tree }`(트리는 `{pane: 번호}` · `{split: 'h'|'v', ratio, a, b}`)를 낸다. `set_layout` 은 1–8 칸.
- **단축키.** `Ctrl+1` · `Ctrl+2` 는 칸 번호 0 · 1 로 간다(이름은 그대로).
- **아직 안 한 것.** `select-layout`·`split-window`·`swap-pane` 같은 명령 이름과 접두키(단계 4), 화면(window)·세션 이름(단계 3·5), 떠 있는 칸, 칸 번호 오버레이(`display-panes`), 칸 ⋯ 메뉴의 「오른쪽으로 나누기 · 아래로 나누기」(`splitPane`·`selectLayout` 은 순수 함수로 있고 UI 는 없다), 저장된 경계선 비율의 옛 localStorage(`iwae:pane-fracs3`, `iwae:pane-grid`)는 읽지 않고 버렸다.

### 단계 2·3 (칸 머리 · 새 맨 위 줄 · 화면 · 템플릿 · 상태 줄)

- **칸 머리.** 모든 칸(하나여도)이 카드 맨 위에 자기 머리를 갖는다: 색 점(8px) · 칸 번호(0 부터, 작고 흐림) · 탭 줄(`PaneTabsMenu`, 끌기·도킹·가운데 클릭 닫기·미리보기 기울임·넘침 그대로) · 흐린 보조 글(탭이 하나일 때 PDF `p.6` · 노트 폴더 · MD 경로) · 상태 자리(비어 있음) · 「크게」일 때 작은 Z · ⋯ 메뉴. 한 줄을 지키려고 **탭이 하나면 알약 바탕 없이 「아이콘 + 제목」, 둘 이상이면 알약 탭 줄이 머리 줄이고 고른 탭만 조금 밝은 알약**으로 했다(제목을 알약 안으로 옮기는 별도 구현은 하지 않았다 — 고른 탭의 이름이 곧 제목이다). 탭 상태 점은 미리보기 탭만(저장 안 됨 점은 안 했다).
- **⋯ 메뉴**(`PaneHead`, `PopupMenu`): 오른쪽으로 나누기 `%` · 아래로 나누기 `"` · 크게/크기 되돌리기 `z` · 새 화면으로 떼기 `!` · 칸 자리 바꾸기 `{ }`(다음 칸과, 맨 끝이면 앞 칸과) · 색 바꾸기 · 칸 닫기 `x`. 키는 힌트만이다(접두키는 단계 4). 한 칸이면 크게·떼기·자리·닫기는 꺼진다. 떼어 낸 창은 나누기·떼기를 끈다. 「되돌리기」는 영어가 Undo 라 한국어 열쇠를 「크기 되돌리기」로 달리 썼다.
- **크게.** 화면마다 `screen.zoomed` 로 저장된다. 예전 「집중 모드」(왼쪽 바도 접힘)와 같은 하나의 동작이다 — 문서 도구줄의 전체 화면 단추도 같은 줄기를 쓴다. tmux 처럼 왼쪽 바를 남기지는 않았다(단순함을 택했다).
- **빈 칸.** 「PDF · MD · 노트 · 캔버스 · 번역기」. PDF 는 파일 선택, MD 는 라이브러리를 펴서 고르게 한다(Markdown 전용 파일 선택은 없다). 노트는 마지막 노트(없으면 새 노트), 캔버스는 마지막/첫/새 캔버스. 번역기는 떠 있는 번역기의 열림 상태만 켠다(문서 칸에 나타남, 문서가 없으면 알림) — 단계 6 에서 떠 있는 칸이 된다. 노트·캔버스는 Vault 가 있을 때만 보인다.
- **맨 위 줄.** 앱 메뉴 · 왼쪽 바 접기 · 사이드바 보기 아이콘 다섯(앱 수준이라 남겼다) · 세션 이름 ▾(「기본」, 메뉴는 「세션은 다음 단계에서」 + 새 화면 템플릿) · 화면 탭 · ⌘ 명령 · 창 단추. 빠진 것: 칸 탭 구역, 「창 나누기」, 「옆에 노트」 단추(Ctrl+Shift+M 은 그대로, 명령 팔레트에 「옆에 노트 열기」). 명령 팔레트 키는 지금 Ctrl+Shift+P 라 단추에도 그 키를 보인다(Ctrl+K 로 바꾸지 않았다).
- **화면 모델.** `Screen = { id, name, layout, panes, channels, zoomed }`(`src/app/screens.ts`). `useVault` 는 `screensState = { screens, activeScreen, lastScreen }` 를 들고 `workspace`(= 보는 화면의 panes·channels·layout)를 파생한다 — 기존 `setWorkspace`·`setPanes` 들은 보는 화면에만 닿는다. 같은 문서 탭이 두 화면에 있어도 된다(복사본). 칸 id 는 모든 화면에서 유일하다(복원 때 `reservePaneIds`, 겹치면 새 id).
- **마운트 선택.** 숨은 화면은 **언마운트**한다(PDF 렌더러가 비싸고, 칸 DOM 을 활성 화면 것만 그린다). 돌아오면 읽던 쪽·배율은 이미 있는 문서별 읽던 위치·보기 설정에서 복원된다. 탭 안 스크롤 위치는 (노트·MD) 탭 전환과 같은 수준으로 복원된다. 화면 전환은 즉시이고 움직임이 없다.
- **템플릿.** 읽기 · 노트 왼쪽 · 비교 · 정리 · 빈 화면(`SCREEN_TEMPLATES`, `buildTemplateScreen`). 「새 화면 ▸ 템플릿」은 보던 문서(복사본)와 마지막으로 만진 노트로 새 화면을 만든다. 팔레트 「이 화면을 템플릿으로 다시 짜기: …」는 예전 프리셋(`applyLayoutPreset`)이라 탭을 닫지 않으며 Vault 가 있을 때만 나온다. 「창 나누기」 고르개(`PdfSplitPicker` 의 상단바 사용)는 없앴다(`PaneToolbar` 안의 PDF 화면 나누기는 별개라 그대로).
- **상태 줄.** `[기본] 0:읽기* 1:비교-` · 칸 n개 · 짧은 알림(`announceAction`) · 명령 힌트 · 접두키 칩(꺼짐) · 「?」(키와 명령 목록, 접두키 키는 「다음 단계」). 설정 「화면 구성 ▸ 아래 상태 줄」(기본 켬)이 꺼지면 상태 줄이 없고 알림은 예전 토스트로 간다. 알림 줄기는 상태 줄이 켜졌을 때 그 높이만큼 올라간다.
- **세션.** `screens`(이름·순서·화면별 layout·paneState·zoomed)·`activeScreen`·`lastScreen` 을 저장하고, 옛 앱이 읽도록 보던 화면의 `layout`·`paneState` 도 같이 쓴다. 단계 1 이전/단계 1 세션은 「읽기」 화면 하나로 옮긴다(`screensFromSession`). 탭 id 목록(`pdfTabIds` …)은 모든 화면의 탭을 한 번씩.
- **신호.** 점 신호·라우팅은 `workspace`(보는 화면)만 보므로 활성 화면의 칸에서만 대상을 찾고, 대상이 다른 화면에만 있으면 예전 대로 보는 화면에 옆 칸으로 연다.
- **MCP.** `app_state.screens: [{index, name, active, panes}]` 추가(`panes`·`layout` 은 보는 화면). 화면 전환·만들기 도구는 안 넣었다 — 단계 4 의 `workspace_command` 로 미룬다. 도구 설명·가이드는 갱신.
- **칸 카드(둥근 타일).** (색 · 테두리는 단계 8 에서 한 카드 두 톤으로 바뀌었다 — 아래 「칸 = 카드 하나, 두 톤」이 현재 모양.) 칸마다 `.pane-card`(반경 `--r-md`, 1px `--divider`, `overflow: hidden`), 칸 사이 틈 `--pane-gap`(6px)과 칸 영역 바깥 여백은 같은 값(투명이 아닌 `--workspace` 테두리 반쪽 + 칸 안쪽 여백 반쪽). 칸막이는 틈 전체가 잡는 자리이고 올리면 틈 가운데에 2px `--accent` 선. 끌기 비율은 테두리를 뺀 안쪽 사각형 기준으로 잰다. 만진 칸은 테두리에 `--accent` 20% + 머리에 4% 기운. Herdr 식 머리·알약 탭·화면 탭·상태 줄 색은 `--paper` `--workspace` `--divider` `--text-strong`(`color-mix`)만 쓴다. 연결선은 본문 DOM 사각형을 재므로 카드 가장자리에서 시작한다(눈으로 확인은 리드 몫).
- **아직 안 한 것.** 접두키·명령줄·`workspace_command`(단계 4), 세션 목록(5), 떠 있는 칸(6), 탭 「저장 안 됨」 점, 칸 머리 상태 자리 채우기, 숨은 화면의 탭 안 스크롤(캔버스 카메라 등) 저장.


### 단계 4 (접두키 · `:` 명령줄 · 키 목록 · `workspace_command`)

- **접두키.** 기본 `Ctrl+Space`. 등록부에 항목 `prefixKey`(일반 묶음)를 두었고, 일반 해석(`resolveShortcut`)은 이 항목을 건너뛴다 — `Ctrl+B` 를 골라도 편집기의 굵게가 먼저 해석되도록. 받는 쪽은 `usePrefixMode`(창 `keydown` capture, 편집기보다 먼저): 글 쓰는 칸 안에서도 먹고, 다음 키는 `stopImmediatePropagation` 으로 편집기에 보내지 않는다. 접두키를 한 번 더 누르면 가로채지 않고 그대로 흘려보낸다(send-prefix: `Ctrl+B` 면 굵게, `Ctrl+A` 면 전체 선택, `Ctrl+Space` 면 아무 일 없음). 2 초 안에 키가 없거나 Esc 면 그만둔다. 상태 줄 「접두키」 칩은 단추라서 눌러도 접두키 모드에 들어간다(입력기가 Ctrl+Space 를 먹는 PC). 설정 「단축키」의 접두키 줄에 `Ctrl+Space · Ctrl+B · Ctrl+A` 프리셋 단추를 두었다(직접 누르기도 된다 — 단 굵게와 겹치는 `Ctrl+B` 는 프리셋으로만 고른다). 명령줄·팔레트 입력칸(`data-prefix-off`)과 단축키 녹음 중에는 접두키를 받지 않는다.
- **다음 키는 `code` 로.** `src/core/prefixKeys.ts` 의 `prefixTokenOf`: 글자·숫자·`Digit`/`Numpad`·기호는 `code` 로, Shift 조합은 `SHIFTED_CODES`(`% " ! { } & ? :` 등)로 읽는다. 한글 입력기가 `key` 를 `ㅋ`/`Process` 로 바꿔도 같다. `code` 가 없는 입력(가상 자판)은 `key` 로. 접두키를 누른 뒤 Ctrl·Alt 를 계속 누르고 있어도 다음 키로 읽는다(Shift 만 구분). Shift·Ctrl 같은 수식 키만 눌린 입력은 기다림을 끝내지 않는다. 접두키 표(`DEFAULT_PREFIX_BINDINGS`)는 키 → 명령줄이고 도움말 표는 `KeysHelpSheet` 의 `PREFIX_KEY_ROWS`(되는 것 · 일부만 · 다음 단계 표시)에 따로 있다.
- **키 표.** 설계 8.2 의 모든 키가 걸려 있다. 되는 것: `% " ← ↑ → ↓ o z x ! { } Space q c , & n p l 0-9 : ?`. 「다음 단계」: `f`(toggle-floating) · `w`(display-popup) · `d`(detach). `s` 는 지금 세션 메뉴(맨 위 줄 「기본 ▾」)를 연다(세션 목록은 단계 5). `,` 는 상태 줄을 `rename-window <지금 이름>` 으로 미리 채워 연다. `&` 는 상태 줄 「화면을 닫을까요? y/n」(y 만 확인, 그 밖의 키·6 초 뒤 그만둠). `q` 는 칸마다 큰 번호(0 부터, 칸 머리 번호와 같다)를 1.5 초 겹쳐 보이고 숫자 키가 그 칸으로 간다(`PaneNumbersOverlay`, 움직임 없음). 방향 이동은 칸 DOM 사각형(`.pane-grid-cell`)으로 가장 가까운 칸을 찾고(맞닿은 칸이 여럿이면 겹친 길이가 긴 칸) 끝에서는 반대편으로 돌아 나간다(tmux 와 같다). 사각형을 못 재면(크게 보는 중·숨은 칸) 트리의 비율 사각형으로.
- **명령 실행기.** `src/app/workspaceCommands.ts`: 순수 파서(`parseCommandLine`: 줄임말 · `;`(따옴표 안·`\;` 는 글자) · 옵션 `-h`/`-t 3`/`-t3` · 따옴표) + 순수 동작(`WorkspaceModel = { screens, activePane }` → 새 모델) + 앱이 하는 일(문서 열기·템플릿·번호 겹침·키 도움말·명령줄 열기 …)을 맡기는 `CommandHost`. 앱(`App.tsx`)은 렌더마다 새 호스트를 만들고 `Proxy` 로 실행기에는 늘 최신 것을 건넨다. `;` 로 이은 명령 사이에서는 `host.settle`(40ms)을 기다려 앞 명령이 바꾼 상태를 다음 명령이 읽는다. 하나가 실패하면 거기서 멈춘다. 파서 오류는 아무것도 실행하지 않는다. 결과 말은 상태 줄 알림으로 뜬다(상태 줄이 꺼져 있으면 토스트).
- **명령.** 설계 8.3 의 지금 되는 것 전부 + 몇 가지 더: `select-pane -n/-p`(다음/앞 칸, `o` 키), `confirm-kill-window` · `rename-prompt` · `command-prompt` · `choose-session`(접두키 표가 쓰는 안쪽 명령, 목록·완성에는 안 나온다), `source-file`(keys.conf 다시 읽기). 정한 것: `split-window` 는 tmux 대로 기본 위아래(`-v`)이고 `-h` 가 좌우; `join-pane` 은 「옆에」라서 기본 좌우(`-h`)이며 `-v` 도 받는다; 크게 보던 중 `split-window`·`select-pane`·`select-layout` 은 크게를 푼다(tmux 의 zoom 해제와 같다); `kill-pane` 이 하나뿐인 칸이면 화면을 닫지 않고 「칸이 하나뿐입니다」; `select-layout` 에 이름이 없으면 화면마다 다섯 배치를 차례로 돈다(`Space` 키); `new-window` 는 템플릿 없이 빈 화면이고 `-t` 템플릿은 이름(읽기 · 노트 왼쪽 …)이나 id(`read` `noteLeft` `compare` `organize` `blank`)로 찾는다; 화면은 번호나 이름(같음 > 앞부분 > 포함 > 글자 차례)으로 찾는다; `open <이름>` 은 문서(표시 이름 → 없으면 경로)·노트·캔버스를 같은 순위 규칙으로 찾아 그 칸의 탭으로 연다(이미 열린 문서는 그 탭이 있는 곳으로 간다). 다음 단계 명령(`new-session` · `switch-client` · `save-session` · `rename-session` · `float-pane` · `embed-pane` · `toggle-floating` · `display-popup` · `new-client` · `detach`)은 읽히고 「다음 단계에서 됩니다」.
- **명령줄(명령 팔레트).** `:` 를 누르면 명령 팔레트가 `:` 로 채워져 열린다(`CommandPalette`, 아래 상태 줄은 단계 8 에서 없앴다): Enter 실행 · Esc 닫기 · ↑/↓ 기록(최근 50줄, localStorage `iwae:command-history:v1`, 같은 줄은 맨 뒤로) · Tab 완성(명령 이름, `select-window -t`·`join-pane -s` 의 화면 이름, `new-window -t`·`apply-template` 의 템플릿 이름, `select-layout`·`set-channel` 인자; 후보가 여럿이면 공통 앞부분과 후보 목록, 이름에 빈칸이 있으면 따옴표). 입력기 조합 중 Enter 는 실행하지 않는다. 상태 줄이 꺼져 있으면 `:` 는 명령 팔레트를 「:」 로 채워서 연다. 명령 팔레트는 「:」 로 시작하는 줄을 같은 실행기로 보낸다. 팔레트 단추 곁 키는 `Ctrl+K`(별칭이 대표 키 `Ctrl+Shift+P` 보다 앞서 보인다 — 등록부의 `commandPalette` 키는 `['Mod+Shift+P', 'Mod+K']` 로 앞의 것이 대표다).
- **keys.conf(해냈다, 작게).** `src/core/keysConf.ts`: `bind-key <키> <명령줄>`, `unbind-key <키>`, `set prefix C-b|C-Space|C-a`, `#` 주석, 틀린 줄은 줄 번호와 함께 건너뛴다. Vault 를 열 때 `.iwae/keys.conf` 를 읽고(`readKeysConf`) `source-file` 로 다시 읽는다. **파일 감시는 하지 않았다.** `bind-key` 는 접두키 다음 키 표 하나만 덮는다(`-n`·`-T`·접두키 없이 쓰는 키는 없다). `set prefix` 는 설정의 단축키 값(`prefixKey`)에 쓴다 — Vault 를 열 때마다 파일이 설정 화면의 선택을 이긴다. 틀린 줄이 있으면 첫 줄만 알린다.
- **MCP `workspace_command`.** `{ command }` → `{ ok, message, state }`. 같은 `runWorkspaceLine`(상태 줄 알림 포함 — 사용자가 AI 가 한 일을 본다)을 거치고, 끝난 뒤 `settle` 을 기다려 `state`(`active_screen` · `active_pane` · 화면별 `{index, name, active, zoomed, panes:[{index, id, active, channel, tabs, active_tab}]}`)를 돌려준다. 명령의 실패는 오류가 아니라 `ok:false` 와 이유(AI 가 고쳐 다시 보내게). 클래스는 `Ui`. Rust 표(`app_tools.rs`)·스키마·`guide.rs`(예시 `split-window -h ; open 노트 A`)에 같이 넣었다. 기존 `set_layout` · `open_document` 는 그대로 두었다(그 위에 다시 만들지는 않았다).
- **손질 셋.** (8) 메모 노트 탭 안의 제목 줄(`NoteTitle` 파일째 없앴다)을 없앴다. 제목 뒤 ⌄ 「노트 열기」 목록은 `NoteHeadMenu`(탭 알약 안 `renderTabExtra`, 목록은 body 에 띄워 탭 줄에 잘리지 않는다), 이름 바꾸기는 칸 머리 제목을 두 번 눌러 그 자리에서(`PaneTabsMenu` 의 `onRenameTab`, 새 노트를 막 만들었을 때 이름 칸을 여는 요청 `requestTitleEdit` 도 여기가 받는다)이고, 검색 · 글 블록 · 펼치기 단추는 서식 줄 오른쪽 끝(`.memo-note-tab-actions`)으로 옮겼다. 검색을 열면 서식 줄 위에 한 줄(`.memo-note-tab-searchrow`)로 나온다. (9) 보조 글은 `PaneHead` 의 따로 요소가 아니라 보는 탭의 제목 바로 뒤 「·」 와 함께 알약 안(`.pane-top-tab-sub`)에 붙고, 탭이 여럿이어도 보는 탭에만 붙는다. 좁아지면 보조 글이 먼저 줄어든다. 닫기 × 는 칸 머리의 모든 알약에서 올리거나 초점이 갈 때만 보이고 자리는 알약 끝에 잡아 둔다(Herdr 식). (10) 맨 위 줄 화면 탭의 「*」 를 뺐다(바로 앞 화면의 「-」 는 남겼다). 상태 줄에는 둘 다 있다.
- **테스트를 바꾼 것.** `Mod+K` 를 쓰던 등록부·단축키 설정 시험은 `Mod+J` 로(Ctrl+K 가 팔레트 별칭이 되었다). 화면 탭 글자(`*`)와 키 도움말(다음 단계 칩이 여럿)을 보던 App 시험을 고쳤다. 메모 노트 탭의 「노트 열기」 시험은 `NoteHeadMenu.test.tsx` 로 옮겼다.
- **아직 안 한 것.** `f`·`w`·`d`·`s`(세션 목록)의 실제 동작(단계 5–7), 세션 · 떠 있는 칸 · `new-client` 명령, keys.conf 의 파일 감시와 `-n`/`-T`, 화면마다 마지막으로 만진 칸 기억(화면을 옮기면 첫 칸을 만진다), `list-keys` 가 키 도움말 창을 여는 것 말고 목록을 따로 내지 않는 것, `open` 이름의 탭 완성, 칸 번호 겹침을 칸 DOM 이 없는 상태(숨은 화면)에서 띄우는 일. 눈으로 확인(상태 줄 입력칸 · 칸 번호 겹침 · 알약 안 보조 글 · 서식 줄 단추)은 리드 몫이다.


### 단계 5 (이름 붙은 세션)

- **저장.** Vault 안 `.iwae/sessions/<이름>.json`(옛 `session.json` 과 같은 내용 = 화면들 · 칸 상태 · 사이드바 값)과 `.iwae/sessions/_last.json`(`{ last, used: { 이름: 마지막 사용 ms } }`)이다. 쓰기는 `writeIwaeFile`(원자 쓰기 · 버전 기록 · 창 사이 직렬화)를 그대로 쓰고, 버전 기록 폴더 이름은 한글 이름이 서로 겹치지 않게 이름의 UTF-8 바이트 16진수로 만든다(Rust `safe_component` 가 영숫자 밖을 `_` 로 바꾼다). 세션 파일은 `isMergeableVaultPath` 의 병합 대상이 아니다(하위 폴더). 앱 창 크기 · 모니터는 원래도 `session.json` 에 없었고(window_state.rs) 그대로다. 코드: `src/core/sessionNames.ts`(이름 검사 · 메타 · 「3분 전」), `src/bridge/vault.ts`(`loadSessions` · `readSessionNamed` · `writeSessionNamed` · `trashSessionNamed` · `removeSessionNamed` · `listSessionNames` · `readSessionsMeta`/`writeSessionsMeta`), `useVault`(`sessionOps`).
- **옮기기.** `loadSessions` 가 `sessions/` 에 세션이 하나도 없고 `session.json` 이 있으면 그것을 「기본」 세션으로 복사해 쓴다(`session.json` 은 **지우지 않고 더는 쓰지도 않는다** — 옛 앱으로 돌아가면 그때 값이 남아 있다). 세션도 `session.json` 도 없으면 아무것도 쓰지 않고(첫 자동 저장이 「기본」을 만든다) 목록은 지금 세션 하나로 본다. 메인 창이 아닌 창(떼어 낸 창 · 새 창)은 옮기지도 쓰지도 않고 읽기만 한다. 이름 검사: 앞뒤 공백 자름 · 빈 이름 · `\ / : * ? " < > |` · 제어 문자 · `.`/`_` 로 시작(`_last`, `.trash` 와 겹치지 않게) · 60자 · 대소문자 무시한 겹침(Windows 파일 이름 규칙)을 막는다.
- **자동 저장 · 바꾸기.** 자동 저장은 이전과 같은 300ms 지연이고 지금 세션 이름 파일에 쓴다. 바꾸기 · 새로 · 갈래 · 이름 바꾸기 · 지우기는 한 줄(`exclusive`)로 차례로 하고, 떠나기 전에 지금 상태를 반드시 저장한다. 바꾸기는 Vault 를 열 때의 복원 코드를 `restoreSessionState` 로 빼서 그대로 다시 쓴다(문서를 다시 열고, 사라진 파일은 `missingDocIds` 로). PDF 보기는 세션을 바꿀 때마다 오르는 `sessionEpoch` 를 칸 DOM 키(`SplitPanes` · `DocumentView`)에 섞어 새로 마운트하고, 읽던 쪽 · 배율은 문서별 읽던 위치에서 돌아온다. **세션을 바꿔도 사이드바 폭 · 접힘은 지금 값을 유지한다**(세션 파일에는 적히지만 바꿀 때 적용하지 않는다 — 바꿀 때마다 사이드바가 튀는 것을 피했다).
- **새 세션 · 다른 이름으로 저장.** 새 세션은 「빈 화면」 하나(빈 칸 하나)이고 **템플릿으로 만드는 것은 하지 않았다**(만든 뒤 화면 탭의 ＋ 로 템플릿 화면을 더한다). 다른 이름으로 저장은 지금 상태를 새 이름으로 쓰고 **그 세션으로 이어 간다**(원래 세션은 떠나기 직전 상태로 남는다). 이름 바꾸기는 새 이름으로 쓰고 옛 파일을 지운다. 지우기는 앱의 휴지통(색인된 문서용이라 맞지 않는다)을 쓰지 않고 `.iwae/sessions/.trash/<이름>-<시각>.json` 으로 옮긴다. 마지막 하나는 지우지 못하고, 지금 세션을 지우면 가장 최근에 쓴 다른 세션으로 먼저 옮긴다. 확인 창은 앱(`ConfirmDialog`)이 띄우므로 `kill-session` 은 바깥 AI(MCP)가 보내도 확인 창만 띄우고 「확인 창에서 …정하세요」로 돌아온다 — 사람이 정한다.
- **세션 메뉴(`SessionMenu`).** 맨 위 줄 「<이름> ▾」 · 접두키 `s` · `list-sessions` · `choose-session` 이 같은 메뉴를 연다. 목록(지금 세션이 맨 앞, 나머지는 최근에 쓴 차례. 화면 수 · 「5분 전」)은 열 때 파일을 읽어 센다. 새 세션 · 다른 이름으로 저장 · 이름 바꾸기는 메뉴 안 입력칸(검사 실패는 칸 아래에)이고, 삭제는 지금 세션을 대상으로 한다(다른 세션은 `kill-session -t 이름`). 「앱 창으로 띄우기」는 꺼 둔 채 「다음 단계」(단계 7). 이전 세션 메뉴에 있던 「새 화면 ▸ 템플릿」 항목은 화면 탭의 ＋ 메뉴와 겹쳐서 뺐다. 상태 줄은 `[이름]` 을 보인다.
- **명령.** `new-session [이름]`(`-s 이름`도) · `switch-client -t 이름`(이름만 써도) · `rename-session 이름` · `save-session [이름]` · `kill-session [-t 이름]` · `list-sessions`(줄임말 `ls`, `new`, `switchc`, `rename`). 명령 줄 Tab 완성은 `switch-client`(첫 인자와 `-t` 뒤) · `kill-session -t` 에 세션 이름을 쓴다(이름에 빈칸이 있으면 따옴표). MCP `app_state.session` 은 `{ name, sessions: [{ name, active, screens, last_used_at }] }`.
- **GitHub 동기화와 `.gitignore`.** 앱의 GitHub 동기화(`src-tauri/src/github.rs`, `src/bridge/github.ts`)는 Vault 를 git 저장소로 다루지 않는다: git 작업 폴더를 `.iwae/github/<이름>/` 에 숨겨 두고 받은 파일만 사용자가 고른 Vault 폴더에 복사한다. 앱이 관리하는 `.gitignore` 가 없으므로 **아무것도 하지 않았다**(열린 질문 「세션을 Vault 안에 둘지」는 그대로다). 사용자가 Vault 폴더 자체를 자기 git 저장소로 쓰면 `.iwae/sessions/` 를 직접 무시해야 한다.
- **아직 안 한 것.** 템플릿으로 새 세션 · 세션마다 사이드바 폭 적용 · 목록의 세션별 삭제 단추 · 같은 Vault 를 연 두 앱 창 사이의 세션 파일 변경 알림(단계 7).

### 단계 6 (떠 있는 칸)

- **모델.** `Screen.floats: FloatingPane[]`(`{ paneId, anchor: {kind:'screen'} | {kind:'pane', paneId}, x, y, w, h, collapsed }`)와 `floatsHidden?`. 칸 자체(탭 · 색)는 보통 칸처럼 `Screen.panes` · `Screen.channels` 에 칸 id 로 들어 있고 나누기 트리에는 없다. 자리 `x · y` 는 붙은 곳 사각형에 대한 비율(0–1), 크기 `w · h` 는 px 이다. 순수 동작은 `src/app/floatingPanes.ts`(`floatPane` · `embedPane` · `toggleFloating` · `closeFloat` · `addFloat` · `openTranslatorFloat` · `toggleTranslatorFloat` · 자리 · 크기 가두기 `floatBoxIn`/`moveFloatBox`/`resizeFloatBox`/`floatFromBox`)이고 `workspaceCommands` · 칸 머리 단추 · 번역기 단추가 같이 쓴다. 한 화면에 4개까지, 최소 크기 240×160, 접으면 머리(34px)만.
- **칸을 따라가기.** 붙은 칸이 트리에서 없어지면(`withActiveWorkspace` · `breakPane` · `join-pane`) `normalizeFloats` 가 화면에 붙이고, 있던 자리를 화면 비율로 바꿔 적는다(크기 px 는 그대로). 트리 동작이 지우는 떠 있는 칸의 색 채널은 `withActiveWorkspace` 가 되살린다. 칸 id 는 모든 화면에서 유일하다(`allScreenPaneIds` 가 떠 있는 칸도 센다).
- **그리기.** `SplitPanes` 의 칸 영역 안, 칸 · 칸막이 뒤에 `FloatLayer` 가 카드로 그린다(z-index 30, 메뉴 400 아래; 더 센 그림자; `floating-panes.css`). 카드는 보통 칸과 같은 껍질 클래스(`.pane-grid-cell` · `.pane-grid-tabs` · `.pane-grid-body`)를 달아 탭 끌어 놓기(`tabDrag`)의 구역 판정과 연결선이 그대로 알아본다. 머리 빈자리(`.pane-float-grip`)를 끌어 옮기고(단추 · 탭 위는 제외) 오른쪽 아래 모서리로 크기를 바꾼다; 끄는 동안은 `FloatLayer` 안에서만 다시 그리고 놓을 때 한 번 `onFloatChange`. 누르면 맨 위(배열 맨 뒤)로 올린다. 접으면 본문을 **마운트한 채 숨긴다**(번역기 입력 · 문서 보기 상태 유지). 크게 보는 중에는 숨은 칸에 붙은 떠 있는 칸을 그리지 않는다. 머리 단추: ▁ 접기/펼치기 · ⇲ 칸으로 넣기 · × 닫기. 떠 있는 칸의 머리에는 칸 번호가 없다.
- **동작 · 명령.** 칸 ⋯ 「띄우기」(`float-pane`, 칸이 하나면 꺼짐) · `embed-pane`(떠 있는 칸을 만지는 중이면 그 칸을, 아니면 가장 위의 떠 있는 칸을 붙은 칸(없으면 만지던 칸) 오른쪽에 나누어 넣음) · 접두키 `f`=`toggle-floating` · 접두키 `w`=`display-popup`(번역기. 같은 곳에 이미 있으면 새로 만들지 않고 숨김 · 접힘을 풀어 만짐; 문서를 보는 칸에서 부르면 그 칸에 붙임) · `display-popup <이름>`(빈 떠 있는 칸을 만든 뒤 `open` 을 그 칸 id 로 부른다. **이미 다른 칸에 열린 탭은 거기서 활성화될 뿐 옮겨 오지 않으므로** 빈 채로 남으면 그 떠 있는 칸을 닫는다). 만지는 칸이 떠 있는 칸일 때 `split-window` 같은 트리 명령은 붙은 트리 칸(없으면 첫 칸)에, `kill-pane` 은 떠 있는 칸 자신을 닫는다. `select-pane -n/-p`(`o`)만 보이는 떠 있는 칸을 돈다; `-t N` · 방향 · 칸 번호(`q`)는 트리의 칸만이다.
- **닫기 · 비우기.** × · `kill-pane` 은 번역기 탭을 버리고 다른 탭은 돌아갈 트리 칸(붙은 칸 → 만지던 칸 → 첫 칸) 뒤에 합친다(탭을 잃지 않는다). 탭을 다 닫거나 끌어내면 그 떠 있는 칸도 닫는다(App 이 「한 번 탭이 있던 칸이 비었다」를 보고 닫는다. 막 만든 빈 칸은 탭이 처음 들어올 때까지 둔다). 탭 끌어 놓기: 떠 있는 칸 가운데로는 옮기기, 떠 있는 칸의 탭을 트리 칸 가장자리로 끌면 거기서 나누기(`dockEdgesFor` 는 떠 있는 칸을 가장자리 대상으로 치지 않아 가운데 구역만 있다). 이 둘은 순수 함수(`moveTabToPaneAt` · `dockTab`)로 시험했고, 포인터로 끄는 DOM 경로는 시험하지 않았다.
- **세션 저장.** `ScreenSnapshot` 에 `floats` · `floatsHidden` 을 더하고, 떠 있는 칸의 탭 · 보던 탭 · 색은 `paneState` 에 칸 id 로 같이 쓴다(옛 세션과 떠 있는 칸이 없는 세션은 모양이 그대로다). 읽을 때 자리 0–1 · 최소 크기로 바로잡고, 다른 화면과 겹치는 칸 id 는 새 id 를 받으며 붙은 칸 id 도 따라간다. 떠 있는 칸의 문서 탭도 탭 id 목록(`pdfTabIds` …)에 들어 다음에 켤 때 다시 열린다.
- **번역기 옮기기.** 새 탭 종류 `translator`(파일 없음, 탭 id `translator:<칸 id>`)가 번역기 탭이다. `TranslatorPanel` 은 머리 줄 · 닫기 · 크기 손잡이 · 떠 있는 자리 계산을 모두 버리고 본문(언어 줄 · 입력 · 번역 · 결과)만 그리는 탭 내용이 되었다. 도구줄의 번역기 단추와 빈 칸의 「번역기」는 그 칸에 붙은 번역기 떠 있는 칸을 열고(이미 있으면 닫는다). 예전 `iwae:translator-panel:v1`(PDF · Markdown 별 열림 · 자리 · 크기)은 시작할 때 **한 번** `migrateLegacyTranslators` 로 옮긴다: 열려 있던 종류마다, 보는 화면에서 같은 종류의 문서를 보는 첫 칸에 붙은 번역기 떠 있는 칸을 만들고(자리는 칸 크기에 대한 비율, 크기는 그대로) 예전 값을 지운 뒤 `iwae:translator-panel:migrated:v1` 을 적는다. 그 종류의 문서가 보이지 않으면 옮기지 않고 버린다(예전엔 문서가 나타나면 같이 나타났다). 번역 설정이 꺼져 있어도 떠 있는 번역기는 뜨고 안내를 보인다. 번역 카드(선택한 글에서 띄우는 것)는 그대로다.
- **연결선.** `setFloatingLinkPanes`(App 이 떠 있는 칸 id 를 알림)와 `pairLinkedPanes` 의 새 규칙: 떠 있는 칸이 상대 칸과 1px 넘게 겹치면 짝을 맺지 않는다(카드 강조만). 겹치지 않는 떠 있는 칸은 보통 칸처럼 이웃 판정으로 짝이 된다.
- **아직 안 한 것.** 떠 있는 칸에 붙은 칸 사각형은 틈 여백을 포함한 칸 셀 기준이라 카드가 실제 칸 가장자리보다 몇 px 안쪽 · 바깥에 놓일 수 있다(눈으로 확인은 리드 몫) · 키보드로 옮기기 · 크기 바꾸기 · 포인터로 탭을 끄는 DOM 경로 시험 · MCP `app_state` · `workspace_command` 의 상태에 떠 있는 칸 목록 · 떠 있는 칸의 키보드 포커스 정책 결정(지금은 `o` 가 돈다) · 칸 번호 겹침에서 떠 있는 칸 표시 · 단계 7(세션에 붙는 여러 앱 창 · `new-client` · `detach`). 눈으로 확인(카드 그림자 · 머리 단추 · 모서리 손잡이 · 접힘)은 리드 몫이다.

### 단계 7 (세션에 붙는 여러 앱 창)

- **동기화 방식: 설계의 「Rust 쪽 세션 저장소」 대신 소유자 창 하나가 상태를 갖는다(방식 a).** 세션마다 **소유자 창**(그 세션에 붙은 앱 창 가운데 메인 창, 없으면 먼저 열린 창)이 있고, 세션 파일은 소유자만 쓴다. 소유자가 아닌 창이 공유 상태를 바꾸면 바뀐 상태 **전체**를 소유자에게 보내고(`iwae:client-intent`), 소유자가 자기 상태에 반영한 뒤 세션에 붙은 모든 창에 새 상태를 알린다(`iwae:client-state`). 소유자가 바꾼 것도 같은 알림으로 퍼진다. 동시에 두 창이 바꾸면 마지막에 온 것이 이긴다(합치지 않는다). Rust 쪽 저장소를 만들지 않은 이유: 이미 있는 Tauri 이벤트(`emit`/`listen`)와 창 label 만으로 되고, 탭 · 문서를 여는 일(PDF 열기, 노트 읽기)이 창마다 웹뷰 안에서 일어나서 Rust 가 상태를 가져도 각 창이 결국 같은 복원 코드를 돌려야 하기 때문이다. 코드: `src/app/sessionSync.ts`(순수 엔진 `ClientEngine`, Tauri 를 모른다), `src/app/useSessionClients.ts`(React 연결), `src/bridge/clients.ts`(Tauri 이벤트 길 · 창 열기 · 숨기기), `src/core/clients.ts`(앱 창 목록 · 소유자 · 닫기 계획 순수 함수).
- **앱 창 목록.** 창들이 「나 여기 있다」(`iwae:client-presence`: 창 id · 이름 · 세션 · 보는 화면 · 숨김 · 열린 시각)를 서로 알려 각자 목록을 만든다. 새 창은 시작할 때 「누구 있나」(`who`)를 묻고 250ms 안에 답이 오면 소유자를 알아본다(그동안은 세션 파일을 쓰지 않는다). 창이 닫히며 `bye` 를 알리고, 알리지 못하고 사라지면(충돌) Rust 의 `on_window_event(Destroyed)` 가 `iwae:client-gone` 을 보낸다. 이름은 메인 창 A, 새 창은 열 때 쓰지 않은 가장 앞 글자(B · C …)를 주소(`client=`)로 받는다. 주소의 새 매개변수: `session=` `screen=` `client=`.
- **공유하는 것과 창마다 따로인 것.** 공유: 화면 목록(이름 · 순서) · 나누기 트리 · 칸의 탭 · 보던 탭 · 미리보기 · 색 채널 · 떠 있는 칸의 위치 · 크기 · 접힘. 창마다 따로(알림에 실리지 않고, 받는 창이 자기 값을 지킨다 — `mergeRemoteScreens`): 보는 화면 · 바로 앞 화면 · 「크게」(`zoomed`) · 떠 있는 칸 숨김(`floatsHidden`) · 사이드바 값 · 칸 포커스 · 스크롤 · 배율 · 열린 메뉴 · 접두키/명령줄 상태. 보던 화면이 다른 창에서 닫히면 그 자리의 이웃 화면으로 간다. 같은 화면을 두 창이 보면 같은 칸을 보이고 포커스와 스크롤은 따로다. 같은 상태인지는 `sharedSessionKey`(창마다 따로인 값을 뺀 JSON)로 비교해, 보는 화면만 바꾼 일은 아무것도 퍼뜨리지 않는다.
- **받은 상태 반영.** 이 창에 이미 열린 탭들만으로 되살릴 수 있으면(탭을 바꾸거나 칸을 나눈 정도) 문서를 다시 열지 않는 가벼운 길(`screensFromKnownTabs`), 새 문서가 있으면 세션을 복원할 때와 같은 코드(`restoreSessionState`)로 열어 온다. 반영하는 동안(약 60ms)의 상태 변화는 「우리가 만든 것」으로 세지 않아 다시 퍼뜨리지 않는다(끝없이 오가지 않는다). 새 창은 파일에서 시작해 곧바로 소유자에게 지금 상태를 요청해 덮는다.
- **새 앱 창(`new-client [-t 세션]`).** 세션 메뉴의 「앱 창으로 띄우기」 · 접두키 없이 `:new-client` · 「새 창」(Ctrl+Shift+N)이 같은 동작이다. 같은 세션이면 열린 창과 다른 화면(다음 화면, 없으면 같은 화면), 다른 세션이면 그 세션이 보던 화면에서 시작한다. 예전 주소(`role=extra` 에 세션 없음)는 빈 탭으로 시작하는 독립 창으로 남겨 두었다(세션을 쓰지 않는다).
- **다른 세션을 다른 창에.** 창이 다른 세션으로 바꾸면(`switch-client`) 떠나는 세션은 소유자였다면 먼저 저장하고 남은 창이 소유자가 된다. 가는 세션에 다른 창이 붙어 있으면 그 창의 두 번째 앱 창이 된다(파일을 읽은 뒤 소유자에게 상태를 요청). 아무도 없으면 이 창이 소유자가 되어 그 파일을 쓴다. 다른 앱 창이 붙은 세션의 **이름 바꾸기 · 지우기는 막는다**(그 창들의 세션 이름이 어긋난다). 다른 앱 창이 붙은 세션을 「저장」하면 「다른 앱 창이 저장합니다」.
- **창을 넘는 색 채널.** `emitPointSignal` 이 채널 있는 신호를 같은 세션의 다른 앱 창에도 보내고(`iwae:client-signal`), 받은 창은 `deliverRemotePointSignal` 로 자기 칸들에 전한다: 보낸 칸은 이 창에 없는 `'@remote'` 이고 `remote: true` 라서 같은 채널의 칸만 그 카드를 열고, 「미리보기 탭 · 새 칸으로 열기」 같은 결정(`routePointSignal`)은 건너뛴다. 받아서 온 신호는 다시 보내지 않는다. 연결선은 창마다 따로다.
- **떼기 · 닫기.** 접두키 `d` = `detach`. 다른 앱 창이 보이면 이 창을 닫고(메인 창이면 아래 「숨김」), **마지막으로 보이는 앱 창이면 상태 줄에서 「앱을 닫을까요? y/n」**(y 만 확인) 를 묻는다. OS 의 × 는 확인 없이 같은 규칙이다(마지막 창이면 앱 종료). 떼어 낸 PDF 창은 이 규칙 밖이다(「다시 붙이기」 그대로, `detach` 는 안내만).
- **소유권 · 메인 창.** 소유권은 목록에서 정해지므로(`ownerOf`) 소유자 창이 닫히거나 세션을 바꾸면 다음 창이 바로 이어받아 쓴다(모든 창이 같은 상태를 들고 있어 잃는 것이 없다 — 창이 닫히기 전에 소유자는 마지막 변화를 한 번 더 쓴다). **메인 창은 닫는 대신 숨긴다**: 다른 앱 창이 보이는 동안 메인 창의 × · `detach` 는 창을 숨겨 둔다(`hide_this_window`). MCP · 자동 백업 · 색인 · 업데이트 확인이 메인 창에서 도는 구조라서, 소유권 이전만으로는 이 일들을 다른 창으로 옮길 수 없기 때문이다. 숨긴 메인 창은 목록에 숨김으로 남고, 마지막으로 보이는 앱 창이 닫히면 메인 창에게 끝내 달라고 부탁해(`iwae:client-quit`) 앱 전체가 끝난다(끝내기 전에 메인 창을 먼저 보여 창 위치를 제대로 남긴다 — `show_app_window`). 숨긴 메인 창을 다시 보이는 길은 앱을 다시 실행하는 것(두 번째 실행이 메인 창을 앞으로 가져온다)이다.
- **MCP.** `app_state.clients: [{ id, label, session, screen }]`(label A = 메인 창, screen 은 0부터). `workspace_command` 는 기본이 메인 창이고 선택 필드 `client`(label 이나 id)로 다른 앱 창을 정한다 — 그 창의 보는 화면 · 만진 칸을 쓰고 결과 `state` 도 그 창의 것이다. 없는 창이면 오류, 8초 안에 답이 없으면 오류. 도구 설명(Rust `app_tools.rs` · `guide.rs`)과 스키마 갱신.
- **권한(capabilities).** 바꾼 것이 없다. 새 앱 창은 기존 `window-*` 패턴에 들고, 창 사이 이야기는 `core:default` 의 이벤트 권한(`emit` · `listen`)으로 되며, 새 Rust 명령(`hide_this_window` · `show_app_window`)은 앱 명령이라 권한 파일에 따로 적지 않는다(`open_app_window` 와 같다). CSP · 보안 설정도 그대로다.
- **세션 메뉴 손질.** 메뉴 폭은 내용에 맞추되 300px 밑으로 줄지 않는다(`.pane-tab-context.pane-tab-context.popup-menu`, 칸 ⋯ 메뉴 · 화면 탭 메뉴도 같은 컴포넌트라 같이 고쳐진다). 오른쪽 힌트는 한 줄(`nowrap`) · 줄지 않음 · 오른쪽 맞춤 · 10.5px 고정폭 · 흐리게. 세션 줄은 「화면 2개 · 앱 창 2개 · 지금」 · 「화면 3개 · 5분 전」. 맨 위 줄 라벨 「앱 창 B」(메인 창에는 없다)와 상태 줄 `[논문 3장 · 앱 창 2개]`(둘 이상일 때만).
- **알려진 한계 · 안 한 것.** 두 창이 동시에 바꾸면 한쪽 변화가 사라질 수 있다(마지막에 온 것이 이긴다 — 한 사람이 모니터 둘로 쓰는 쓰임을 가정했다). 새 창이 소유자의 상태를 받기 전(약 0.3초) 바꾼 것은 받은 상태에 덮인다. 같은 화면의 칸 포커스 · 스크롤을 창 사이에 맞추는 일은 하지 않는다(따로가 규칙이다). 숨긴 메인 창을 앱 안에서 다시 꺼내는 단추 없음. 메인 창 밖(새 창)에서 MCP · 백업 · 색인을 하지 않는다. Rust 쪽 세션 저장소는 만들지 않았다. 눈으로 확인(상태 줄 · 「앱 창 B」 라벨 · 세션 메뉴 폭)과 실제 두 창 실행은 리드 몫이다.

### 단계 8 (한 면 · 한 높이 · 상단바 도구줄, 2026-11-13)
- **아래 상태 줄을 없앴다.** `StatusBar` · `status-bar.css` · 설정 「아래 상태 줄」 토글(`appPrefs.statusBar`)이 없다. 짧은 알림은 오른쪽 아래 알림 줄기의 토스트(`announceAction`)로만 간다. `:` 는 명령 팔레트가 `:` 로 채워져 열리는 것 하나가 명령줄이다(`CommandPalette` 가 Tab 완성 · ↑↓ 기록을 이어받았다). 접두키 대기(`prefix`) · 「화면을 닫을까요? y/n」(`confirm`)는 상단바 바로 아래 가운데의 작은 칩(`PrefixChip`, `Ctrl+B …`)으로, 대기 중에만 그려진다(자리 차지 · 움직임 없음, 눌리지 않는다). 키 목록은 접두키 `?` 와 팔레트의 「키와 명령 보기」. 맨 위 줄 「⌘ 명령」 단추도 없다(Ctrl+K · Ctrl+Shift+P). 상단바 밑선도 없다.
- **칸 = 카드 하나, 두 톤.** `.pane-card` 하나에 머리(탭 줄)는 `--pane-surface`(= `--paper`), 본문 · 아래 막대는 `--pane-body`(= `--workspace`)로 머리 아래 4px 를 띄우고 카드 가장자리까지 채우며, 안에 선 · 띠가 없다. 탭은 28px 알약 한 모양(고른 탭만 옅은 바탕). 만지는 칸은 `PaneCard` 의 `pane-card-active` 로 카드 테두리가 1.5px 강조색(밝은 화면은 80%), 나머지는 옅은 테두리. 빈 칸은 같은 1.5px 점선(`data-empty`, 만지면 강조색 점선). 채널 색은 카드 테두리 전체(`data-channel`: 쉬는 칸 35% · 만지는 칸 100%, 채널 없음은 `--divider` → `--accent`)이고 머리의 색 점은 바꾸는 단추로 그대로 있다. 모두 `workspace-surface.css`(theme.css 에서 whale-theme 뒤에 불러온다).
- **칸 반응 표시.** `paneReaction.reactingPanes`(순수): 같은 채널에서 그 메모 · 문서를 보여 주는 다른 창. 메모 카드 · PDF/MD 형광펜에 마우스를 올리는 동안 그 창들 카드에 채널 색 안쪽 윤곽(`data-reacting`), 신호가 실제로 창을 움직였을 때(`usePointSignalReceiver` 가 true)는 0.6초 윤곽. 정적(opacity 만). 캔버스 블록 올림은 캔버스가 꺼져 있어 연결하지 않았다(순수 함수는 캔버스 칸도 안다).
- **도구줄은 상단바에.** 화면 탭과 창 단추 사이의 도구줄 자리(`TopBar` 의 `.topbar-toolbar-host`, `.pane-doc` 별칭)에 지금 만지는 칸(떠 있는 칸 포함)의 도구줄만 포털로 그려진다(`topBarToolbar.tsx`): MD · PDF 의 `PaneToolbar`, 노트의 서식 줄 + 검색 · ＋ · 펼치기. 넘치면 `PaneToolbar` 의 「⋯」 가 접는다. 빈 칸 · 캔버스는 자리가 빈다. 한 글자 단축키는 `useOverlayToolShortcuts` 로 문서 칸이 받는다. 상단바 자리가 없으면(시험 · 단독) 예전처럼 칸 안에 둔다.
- **번역기는 다시 창 하나.** 탭 종류 `translator` · 번역기 떠 있는 칸을 없앴다. `TranslatorPanel` 은 앱 창 전체에 떠 있는 창(340×300, 상단바 아래 어디로든 끌고 크기 조절, 상태는 `iwae:translator-window:v1`). 도구줄 번역기 단추 · 접두키 `w` · `display-popup`(이름 없음)이 연다. 예전 세션의 번역기 칸 · 탭은 읽을 때 버리고(`withoutTranslatorFloats`) 그 자리 · 크기로 창을 연다(`SessionState.legacyTranslator`). 빈 칸의 「번역기 띄우기」 · 「캔버스 열기」 줄도 없다.
- **높이 · 간격.** `--bar-h` 36px 한 값(상단바 · 칸 탭 줄 · PDF/MD 아래 막대), 아이콘 단추 `--icon-btn` 28px · 아이콘 `--icon-size` 16px, 안쪽 여백 8/12/16 · 형제 사이 4, 칸 사이 틈 · 바깥 여백 `--pane-gap` 6px. 사이드바 보기 탭은 탭 모양(아래 왼쪽 바와 이어짐)을 그대로 둔다.
- **캔버스는 껐다**(`CANVAS_ENABLED = false`, Rust `canvas_tools::ENABLED = false`): 사이드바 캔버스 구역 · 새 캔버스 · 「정리」 템플릿 · 캔버스 명령이 빠지고 세션의 캔버스 탭은 조용히 건너뛴다. 코드는 그대로다.
- **움직임 정리.** 연결선 다시 그리기 · 노트 블록 튀는 선택 · 메뉴 스프링은 120ms 페이드로, 형광펜 깜빡임은 400ms 한 번, 탭 끌기는 넘치지 않는 ease-out, `pane-appear` · `pane-grow-in` 은 삭제.
- **끌어 놓기 다듬기(탭 · 왼쪽 바).** 놓을 자리는 마우스 밑 요소가 아니라 칸 상자의 자리(`paneHitAt`: 칸 사이 틈 · 경계선도 가까운 칸)로 정한다. 끄는 동안 `body.pane-tab-dragging` / `body.dock-dragging` 이 칸 안 내용 · 머리(탭 끌기는 왼쪽 바 · 상단바도)의 마우스를 막아 올려 둔 카드가 들뜨지 않는다. 미리보기는 머리까지 든 칸 카드 전체 기준이고, 미리보기가 보이면 놓으면 꼭 된다: `allowedDockEdges`(`dockEdgesFor` 가 쓴다)가 칸 상한 · 최소 크기(240×160)로 못 나누는 가장자리를 빼고, 그쪽은 「가운데(이 칸으로 옮기기)」로 본다. 하나뿐인 탭을 다른 칸으로 끌면 칸 수 상한은 그 칸이 닫힌 뒤로 센다. 들린 탭(ghost)은 머리 바탕 없이 탭 하나만이고, 원래 탭은 점선 구멍(× · 고른 탭 바탕 없음)이다.
- **왼쪽 바 → 칸 끌어 놓기.** 문서(PDF · Markdown) 줄과 노트 줄을 칸으로 끌어 연다(`dockSession.ts`, 탭 끌기와 같은 구역 · 미리보기 · 탭 줄 틈): 칸 가운데 = 그 칸에 보통 탭(미리보기 탭 아님), 가장자리 = 갈라 새 칸에 열기, 빈 칸 = 그 칸에 열기, 탭 줄 = 놓은 자리에 끼우기. 이미 열려 있으면 그 탭을 옮긴다(`dropTabAt`). 끄는 것은 줄의 아이콘 + 이름 알약 하나이고, 복사 커서는 받을 수 있는 자리(트리 · 칸)에서만 난다. 노트 목록은 포인터가 목록 밖으로 나가면 놓을 자리 줄을 거두고 놓아도 차례를 바꾸지 않는다. 폴더 · 여러 줄 · 캔버스는 칸으로 못 연다(트리 안에서만 옮긴다). 포인터 경로(`startTreeDrag` · `MemoNotesSection.startPress`)는 jsdom 시험(`Sidebar.test` · `MemoNotesSection.test` · `dockSession.test`)으로 못박았고 실제 모양은 CDP 로 봤다.

### 단계 8 손질 1차 (검토 1회차, 2026-11-13)
- **번역기 창 상태는 창끼리 나눠 갖는다.** 앱의 모든 창(메인 · 세션에 붙은 새 창 · 떼어 낸 창)이 같은 `iwae:translator-window:v1` 을 그리고, 다른 창이 바꾸면 `storage` 이벤트로 다시 읽는다(낡은 값으로 덮어쓰지 않는다). 한 창에서 열면 다른 창에도 같은 자리에 열린다. 상단바 높이는 `TOPBAR_HEIGHT_PX`(= `--bar-h`, 시험이 같은지 본다) 한 값.
- **번역기를 여는 키 · 명령.** 접두키 `w` · `display-popup`(이름 없음) · 팔레트의 「번역기 열기」는 설정에서 번역을 꺼 두었으면 열지 않고 「번역이 꺼져 있습니다」 를 알린다. 열리면 입력칸에 포커스가 간다(다른 창의 동기화로 열릴 때는 빼앗지 않는다). 도구줄 단추는 그대로 토글이다.
- **예전 세션의 번역기 탭.** 떠 있는 칸뿐 아니라 나누기 트리 칸에 저장된 `translator:pN` 탭도 읽을 때 버린다(번역기 탭만 있던 칸은 트리에서 접고, 하나뿐인 칸은 빈 칸으로 남는다). 접어 두었거나 「모두 숨김」 화면의 번역기 칸이었으면 창을 열지 않는다(`LegacyTranslatorFloat.collapsed · hidden`).
- **캔버스 탭은 지나간다.** `CANVAS_ENABLED=false` 인 동안 되살리지 않은 캔버스 탭 id 를 `dormantTabsOf` 로 칸별로 기억했다가 `captureSession` 이 같은 칸 뒤에 그대로 다시 적는다(노트 탭 목록에도). 칸이 닫히면 같이 사라진다. 캔버스를 다시 켜면 탭이 돌아오고, 빈 칸의 「캔버스 열기」 줄도 `onCanvas` 로 되살아난다(꺼 둔 동안 App 이 주지 않는다).
- **한 글자 도구 단축키(T · P · L …)** 는 그 문서 칸을 만지고 있을 때만 듣는다(`DocumentView.paneActive`). 노트 칸을 만지는 동안은 서식줄이 상단바에 있으므로 건드리지 않는다.
- **칸을 누르면(`PaneCard`)** 왼쪽 단추 · 아직 만지지 않은 칸일 때만 그 칸이 된다. 탭을 누른 것은 끌기의 시작일 수 있어 놓을 때(4px 이내)로 미뤄, 끄는 동안 상단바 도구줄이 바뀌지 않는다. `focusPane` 도 이미 그 칸이고 경로도 같으면 아무것도 하지 않는다.
- **노트 서식줄은 상단바에만.** 노트 칸이 만지는 칸이 아닐 때는 카드 안으로 뛰어들지 않고 아무것도 그리지 않는다(글이 밀리지 않는다). 검색 · 글 블록 · 펼치기 묶음은 오른쪽 끝이 아니라 서식 단추 바로 뒤(구분선 다음)에 이어 붙고 남는 자리는 그 뒤에 온다. 서식줄이 쓸 수 있는 폭은 도구줄 폭에서 곁의 묶음을 뺀 값(`formatCapacity`)으로 잰다.
- **명령 팔레트는 로고(앱) 메뉴에도 있다**: 「명령 팔레트」(단축키 표시) · 「키와 명령 보기」. 명령줄 기록은 글을 고치면 ↑↓ 자리를 끝으로 돌리고 고친 줄을 새 줄로 삼는다.
- **칸 도구줄 상태는 칸마다 기억한다**(`paneToolbarMemory`): 칸을 옮겨 만져 도구줄이 다시 그려져도 넘침 단계 · 검색 단추(고정 · 펼침)가 이어진다.
- **왼쪽 바에서 이미 다른 칸에 열린 문서를 끌어 놓으면** 탭 끌기와 같이 그 탭을 옮긴다(복제 없음, 비면 원래 칸이 닫힌다) — `dropTabAt` 시험으로 못박았다. 놓을 자리 판정 · 표시는 `resolveDockTarget` · `paintDockTarget` · `buildGhostShell` 하나를 탭 끌기와 왼쪽 바 끌기가 같이 쓰고, 나눌 수 있는 가장자리는 `dragDockEdges` 하나다. 탭 줄 틈은 알약 너비 + 탭 줄의 실제 `column-gap`(예전 3px 상수는 실제 4px 와 어긋났다).
- **CSS 정리.** 옛 크롬 탭 규칙(theme-layout · whale-theme · pdf-memo)을 걷어 알약 탭 규칙은 보통 선택자 한 벌(`.pane-head .pane-top-tab`)이다. 구멍 점선 칸(`::before`)은 `tab-drag.css` 한 곳, 아래 막대(`.pane-bottom-bar`)의 자리 · 높이 · 여백은 `workspace-surface.css` 한 규칙, 상단바 도구줄 자리는 `.pane-doc` 별칭 없이 자기 규칙(`.topbar-toolbar-host …`). 높이 별칭 토큰(`--topbar-h` · `--toolbar-height` · `--tabbar-h` · `--bottom-bar-height`)은 없애고 `--bar-h` 를 바로 쓴다. 좁은 탭(76px 이하)은 아이콘만 남아도 알약 바탕을 지킨다. 빈 칸의 키 힌트는 접두키 칩 · 팔레트와 같은 UI 글꼴 키캡이다.

### 단계 8 손질 3차 (검토 3회차, 2026-11-13)
- **탭 끌기 뒤의 click 막기는 시간이 아니라 놓을 때까지다.** `PaneTabsMenu` 는 끌기가 시작될 때(`onDragged`)부터 막기를 켜고, 놓은 뒤(pointerup · pointercancel) 한 틱(`setTimeout 0`) 뒤에 푼다. 새로 누르면(pointerdown) 바로 푼다(창이 따로 움직여 pointerup 이 안 오는 끌기도 갇히지 않는다). 예전 400ms 고정 시간은 오래 끌다 Esc 로 취소하고 탭 위에서 놓으면 새던 click 을 못 막았다.
- **누르기 규칙 하나(`PaneCard`).** 끌기 문턱과 같은 `TAB_DRAG_THRESHOLD_PX`(6px, 예전 4px 는 따로였다). 탭 닫기 ×는 닫는 것 말고는 아무것도 하지 않고(칸도 만지는 칸이 되지 않는다), 탭의 오른쪽 여백은 탭처럼 놓을 때 칸이 바뀐다. 기다리는 동안 Esc · blur · pointercancel 로 누름이 취소되고 새 누름이 오면 먼저 누름의 창 리스너를 걷는다. `.pane-focus-scope` 도 왼쪽 단추일 때만 칸을 바꾼다.
- **menuGuard 는 포인터가 진짜 움직일 때까지.** 메뉴 항목(`role=menuitem`) · 목록 고르기 항목(`role=option`, 앱 `Select` 포함) · 탭 목록 뒷판(`.pane-tabs-backdrop`)을 누르면 켜지고, `movementX/Y` 가 0 이 아닌 첫 pointermove 나 새 누름(pointerdown)에서 꺼진다(레이아웃 뒤 브라우저가 만드는 합성 move 는 움직임이 0 이다). 모든 호버 경로가 이것을 본다: `NoteFlow` 카드 pointerenter, `MemoNoteTabView` pointerover, `MarkdownPane` pointermove, PDF 형광펜 호버(`SelectionLayer`). 비켜 간 진입은 같은 카드 위에서 포인터가 진짜 움직이면 그때 켠다(카드는 `onPointerMove` 에서 다시 본다). 앱 · 메뉴 컴포넌트의 부수 효과 import 는 걷었다(쓰는 쪽이 `menuGuardActive` 를 부르면 같이 깔린다). 손질 2차의 「350ms」 는 이것으로 바뀌었다.

### 단계 8 손질 6차 — 메모 블록 노트 사이 끌기 (2026-11-13)
- **끌기 모양(ghost).** 블록 끌기(같은 노트 순서 바꾸기 포함)에 카드의 작은 복사본이 잡은 자리를 그대로 두고 따라온다(`createBlockGhost`, `note-block-drag.css`). 폭 최대 280px, 세 줄쯤만 보이고 아래는 옅어진다, 바탕은 카드 바탕 · 1px `--divider` 선 · 카드와 같은 둥글기 · 탭 ghost 와 같은 그림자, 불투명도 0.95, 크기·기울기 변화 없음. 여러 블록(고른 블록 · 소제목 묶음)이면 오른쪽 위에 개수 배지. 원래 카드는 예전처럼 흐려진다.
- **노트 사이 옮기기.** 끄는 동안 다른 칸(트리 칸 · 떠 있는 칸)에 보이는 메모 노트 위로 가면 그 노트 안에 같은 놓을 자리 줄(가운데선 규칙, `dropBeforeIdAt`)이 뜨고 그 칸에 은은한 안쪽 테두리(`note-block-drop-pane`)가 생긴다. 가장자리 30px 에서는 받는 노트가 스크롤한다. 놓으면 받는 노트에 먼저 쓰고(`moveBlocksBetweenNotes`), 쓴 것이 확인된 뒤에만 원래 노트에서 뺀다. 실패하면 「블록을 옮기지 못했습니다」를 알리고 원래 노트는 그대로. 두 노트를 `recordSeparately` 한 묶음으로 쓰므로 Ctrl+Z 한 번에 둘 다 돌아온다. 소제목은 묶음째, 여럿을 고른 채 끌면 고른 블록 모두(문서 차례) 간다. 소제목 하나를 끌면 받는 노트에서도 다른 묶음 한가운데로 안 들어가고 다음 소제목 앞(없으면 끝)에 놓인다(`snapBeforeId`). 받는 노트에 이미 같은 형광펜이 있는 메모는 옮기지 않고 원래 노트에 남기며 「이미 이 노트에 있는 메모입니다」를 알린다. 같은 경로 노트가 두 칸에 열려 있으면 같은 노트로 보고 순서 바꾸기로 처리한다. 놓은 뒤 받는 노트가 그 블록으로 스크롤한다(`revealNoteBlock`). 칸이 노트가 아니거나 아무 데도 아니면 아무 일 없이 원래 노트 순서 바꾸기가 그대로 된다.
- **Alt = 링크 · 복사.** 놓는 순간 Alt 가 눌려 있으면(누르고 뗄 때마다 바로 바뀐다) 옮기지 않고 받는 노트에 새 블록을 더하고 원래 노트는 그대로 둔다. 메모 블록은 같은 형광펜(첫 원문 + 더한 원문)을 가리키는 새 블록 — 메모 글은 형광펜의 것이라 같이 보이고, 읽는 모양이 같도록 ID·제목(ticket)도 베낀다(같은 ID·같은 형광펜 블록은 `setTicket` 이 노트 사이에서 함께 맞춘다). 글·소제목은 새 id 의 복사본. ghost 왼쪽 아래에 링크 아이콘 + 「링크」(메모가 하나라도 있을 때) 또는 복사 아이콘 + 「복사」 이름표, 받을 노트 위에서는 복사 커서. 받을 노트가 없는 자리(원래 노트 위 포함)에서는 이름표가 흐려지고 놓아도 아무 일 없다(같은 노트에 사본이 생기지 않게; 순서 바꾸기도 하지 않는다). 끄는 동안 Alt 의 keydown · keyup 은 막아 Windows 창 메뉴가 포커스를 가져가지 않게 한다. 이미 받는 노트에 있는 형광펜은 링크하지 않고 같은 안내를 한다.
- **탭 위에 머물러 열기(spring-load).** 끄는 동안 어느 칸이든 머리의 메모 노트 탭 알약 위에 450ms 머물면 그 탭이 보이는 탭이 되어 이어서 놓을 수 있다(탭의 일반 hover 모양 그대로, 새 표시 없음, 노트가 아닌 탭은 아무 일 없음). 노트 탭 알약 위에 바로 놓으면 그 노트의 맨 끝에 붙는다(옮기기, Alt 면 링크 · 복사) — 보이지 않는 노트라 탭을 열지는 않는다. 끄는 동안 `.pane-grid-body` 안은 마우스를 받지 않고(`note-block-drag.css`) 머리의 알약은 받는다.
- **Esc** 는 끌기 전체를 그만둔다(capture + stopPropagation, 아무것도 안 바뀐다). pointercancel 도 놓은 것으로 치지 않는다(전에는 놓은 것처럼 순서를 바꿨다).
- **연결선 · 형광펜↔노트 연결**은 노트 내용에서 파생되므로(`notesOf` · 카드 배치) 따로 손볼 것이 없다.
- 코드: 판단 함수는 `core/memoNote.ts`(`carriedBlocks` · `snapBeforeId` · `moveBlocksBetweenNotes` · `linkBlocksInto` · `copyBlock`), 모양 · 놓을 곳 찾기 · 세션은 `pdf/noteBlockDrag.ts`. 칸 안에서 받는 노트는 `MemoNoteTabView` 의 스크롤 칸 `data-note-path` 로 알아본다(Markdown · PDF 쪽 노트 바는 받는 곳이 아니라 끌어 내는 쪽으로만 쓴다).

### 단계 8 손질 6차 — 칸 통째로 끌기 · 노트 · Markdown 탭 떼어 내기 (2026-11-13)
- **칸 머리를 잡고 칸을 끈다**(`paneDrag.ts`, 포인터 이벤트로 직접). 트리 칸 머리의 빈자리 · 칸 번호를 누르고 `TAB_DRAG_THRESHOLD_PX` 이상 움직이면 시작한다. 탭 · 색 점 · ⋯ 등 단추 · 탭 목록은 제외(`isPaneDragPress`). 떠 있는 칸의 머리는 예전대로 칸 자체를 옮긴다(`.pane-float-head`는 제외, 떠 있는 칸은 놓을 대상도 아니다). 칸이 하나뿐이거나 크게 보는 중이거나 라이브러리를 크게 펼친 중이면 끌 곳이 없어 시작하지 않는다.
- **모양.** 손에는 작은 알약(칸 번호 + 보는 탭의 아이콘 · 이름, 탭이 없으면 「칸 N」)이 붙는다(`createPillGhost` — 탭 끌기의 들린 탭과 같은 껍질). 원래 칸 카드는 점선 테두리 · 반투명 · 옅은 강조색 덮개(`data-pane-dragging`, `pane-drag.css`, 120ms 투명도). 끄는 동안 body 에 `dock-dragging`(칸 안 내용에 마우스가 걸리지 않는다). 놓으면 알약은 120ms 로 투명해진다(움직임 줄이기면 바로).
- **놓을 자리**는 탭 끌기와 같은 판정(`paneHitAt` · `resolveDockTarget` · `paintDockTarget`)이다: 다른 칸의 **가장자리** = 그 쪽에 나누어 넣어 옮기기(`movePaneToEdge`: 원래 자리에서 빼면 형제가 자리를 채우고, 칸 id 가 그대로라 탭 · 색 채널 · 칸마다의 상태가 따라간다), **가운데나 머리 줄** = 두 칸의 자리 맞바꾸기(`swapPanes` = `swapLeaves`). 제 칸 · 칸 밖 · 떠 있는 칸 위 · Esc · pointercancel = 취소. 미리보기가 보이는 자리는 놓으면 꼭 된다: 대상이 너무 작아지는 가장자리(240×160)는 `paneMoveEdges` 가 미리 빼서 가운데(맞바꾸기)로 본다. 칸을 빼고 다시 끼우니 칸 수 상한은 걸리지 않는다. 바로 옆 칸을 옮길 때는 뺀 자리까지 대상 몫으로 센다(`sizeAfterRemoval`). 끝난 칸이 만지는 칸이 된다.
- **눌러서 칸 만지기는 그대로다**(누르는 순간 그 칸이 만지는 칸 — `workspaceSurface.test` 가 못박은 규칙이라 놓을 때로 미루지 않았다. 끄는 것은 그 칸 자신이라 다른 칸의 도구줄로 넘어가지 않는다). 끌고 난 뒤의 click 은 한 번 삼킨다(놓은 뒤 한 틱, 새로 누르면 바로 푼다).
- **노트 · Markdown 탭 떼어 내기**(tmux 의 break-pane + new-client). 메모 노트 · Markdown 탭을 창 밖(또는 가장자리 360ms 머물기, PDF 와 같은 문턱)으로 끌면 탭이 **같은 세션의 새 화면(칸 하나)**에 담기고(`tearTabToScreen`, 보던 화면은 그대로 · 원래 칸은 비어도 닫지 않는다 — 하나뿐인 칸의 마지막 탭이면 빈 칸이 남는다 · 새 칸은 원래 칸의 색을 받는다), 그 화면을 보는 **새 앱 창**(`window-*`, 세션에 붙는 extra 창)이 마우스를 따라온다. PDF 는 예전대로 떼어 낸 PDF 창이다(캔버스는 아직 떼어지지 않는다).
  - **새 창이 어느 화면을 보는가.** 앱 창은 각자 보는 화면이 따로다(tmux 의 client). 새 창 주소의 `screenid=<화면 id>`(번호 `screen=` 보다 우선, `WindowMode.screenId`)로 정한다 — 새 화면은 세션 파일에 쓰이기 전일 수 있어서, 파일에 있으면 바로 그 화면에서 시작하고(`useVault`), 없으면 소유자 창이 보내 주는 상태(`applyRemoteSession`)에 그 화면이 처음 올 때 한 번 그리로 간다(`wantedScreenRef`).
  - **Rust**: `begin_tab_drag` 의 `kind`(`"detached"` 기본 · `"extra"`)로 따라올 창의 종류를 고른다(`drag_window_kind`, 시험 1개). 그 밖의 흐름(창이 마우스를 따라감 · 탭 줄 자리 알림 · 놓음 알림)은 PDF 와 같은 길이다. 권한 · CSP · 보안 설정은 그대로(새 명령 없음, 이벤트 `iwae:tab-attach` 하나가 늘었고 `core:default` 의 이벤트 권한으로 된다).
  - **다른 앱 창의 탭 줄에 놓으면** 그 창에 붙는다: 놓은 창(떼기를 시작한 창)이 `iwae:tab-attach`(탭 id · 칸 · x)를 대상 창에 보내고, 대상 창이 새 화면에서 탭을 가져와 놓은 자리(탭 줄이 벌려 둔 곳)에 넣고(`attachTabToPane`) 비어 버린 새 화면은 닫는다. 떼기를 시작한 창은 그 뒤 떼어 낸 창을 닫는다. 대상이 다른 세션의 창이거나 빈 곳이면 창은 놓인 자리에 그대로 둔다. 같은 창의 탭 줄에 놓아도 같다(자기 창이 받는다).
  - **남은 것 · 알려진 한계.** 새 창의 크기는 메인 창 설정 그대로이고 마우스는 기본 사이드바(280px) 오른쪽 첫 탭쯤에 온다(`TORN_CLIENT_GRAB_X/Y`) — 사이드바 폭이 다르면 조금 어긋난다. 두 창이 같은 노트를 동시에 여는 것은 예전 새 앱 창과 같은 한계다. 떼어 낸 PDF 창(detached) 안에서 노트 탭을 끌어내는 것은 안 한다(세션이 없다). 눈으로 확인(창이 마우스를 따라오는 모습 · 다른 창 탭 줄에 붙기)은 실제 두 창 실행이 필요하다.
- 코드: 순수 규칙은 `paneMove.ts`(`paneMoveEdges` · `movePaneToEdge` · `swapPanes`)와 `tabTearOff.ts`(`tearTabToScreen` · `attachTabToPane`), DOM 은 `paneDrag.ts`, 시험은 각 `.test.ts` 와 `PaneTabsMenu.tearoff.test.tsx`(PDF · 노트 · Markdown 은 떼어지고 캔버스는 안 된다).

### 단계 8 손질 6차 — 색 점 끌어 잇기 · 같은 색 칸 셋 이상 (2026-11-13)
- **색 점을 끌어 다른 칸에 놓으면 잇는다.** 점(`ChannelDot`)을 누르고 `TAB_DRAG_THRESHOLD_PX` 이상 움직이면 끌기가 시작되고(`channelDrag.ts`), 움직이지 않은 누름은 예전처럼 색 바꾸기다. 끌기 뒤에 따라오는 클릭 한 번은 삼킨다(Esc 로 끝났으면 손을 뗀 뒤 클릭까지). 끄는 동안 12px 점(채널 없는 칸은 점선 고리)이 포인터를 따라오고, 점 가운데에서 포인터까지 1.5px 선(전체 화면 SVG, 포인터를 받지 않는다)이 이어진다 — 움직임은 따라오기뿐이다. 놓을 칸은 `paneHitAt`(트리 칸 · 떠 있는 칸의 머리 · 본문)으로 찾고 카드 테두리가 놓으면 될 색 100% 로 미리 보인다(`data-link-preview`, `workspace-surface.css`). 자기 자신 · 빈 곳 · 상단바 위는 취소, Esc 도 취소. 끄는 동안 body 에 `dock-dragging` 을 달아 칸 안 내용에 마우스가 걸리지 않게 한다. 점의 `pointerdown` 은 `stopPropagation` 이라 머리 전체 끌기가 점에서 시작하지 않는다. 점의 말풍선 · 접근성 이름에 「다른 칸으로 끌어 잇기」가 들어갔다.
- **잇는 규칙**(`channelLink.ts`, 순수): 끈 칸에 채널이 있으면 놓은 칸이 그 채널을 받는다. 끈 칸이 채널 없음이면 두 칸을 뺀 다른 보이는 칸이 쓰지 않는 첫 색(파랑 · 초록 · 주황 차례), 모두 쓰면 파랑을 두 칸 모두에 준다. 놓은 뒤 두 칸을 `flashReaction` 의 신호 테두리로 잠깐 켜고 알림은 하지 않는다. App 이 `setChannelDragHost` 로 보이는 칸 · 채널 · 잇기를 대 준다.
- **같은 색 칸이 셋 이상(개수 제한 없음).**
  1. 이미 그 문서 · 노트를 보이는 같은 색 칸은 모두 반응한다(받는 쪽이 스스로 — 메모 신호는 원래 그랬고, 위치 신호(AI · 검색)의 쪽 넘기기도 이제 보이는 같은 색 문서 칸 모두에 한다).
  2. 내용을 바꿔야 하면 한 칸만 바뀐다: 같은 색의 맞는 종류 칸 중 **가장 최근에 만진 칸**에 미리보기 탭이 열리고, 탭을 여러 칸이 갖고 있으면 그중 가장 최근 칸에서 활성화한다(`resolvePointSignal` · `placeNoteTab` · `closeNoteBeside` 의 `mru`). 최근 기록이 없는 칸끼리일 때만 미리보기 탭이 이미 있는 칸을 먼저 쓴다(예전 규칙은 비김 규칙으로 남았다). 칸을 만진 차례(`paneRecency.ts`, 앞이 최근)는 App 이 `activePaneId` 가 바뀔 때마다 갱신한다 — **저장하지 않는다**(세션 파일에 없다): 앱을 다시 열면 만지는 칸 하나만 알고 나머지는 화면 차례가 비김 규칙이다. 칸 id 는 화면끼리 겹치지 않으므로 앱 전체에 목록 하나(상한 48)다.
  3. 새 메모는 하나의 노트로: 문서 칸이 만든 메모는 같은 색 노트 칸 중 가장 최근에 만진 칸이 지금 보이는 노트로 간다(`memoNoteTargetFor` · `visibleNotePathsIn` 의 `mru`). 그 노트는 PDF · Markdown 도구줄 맨 끝(앱 묶음 앞)의 흐린 칩 「→ 노트 이름」(`MemoTargetChip`, 약 160px 말줄임, title 은 전체 이름)으로 보인다. 같은 색 노트 칸이 없으면 칩도 없고(예전처럼 옆에 노트를 연다) 칸이 약 420px 보다 좁아도 숨긴다.
  4. 연결선은 이웃한 칸 사이에만: 예전 규칙(`neighborSide`, DOM 사각형으로 가로 틈 12px · 세로 겹침 24px)이 이미 그랬다 — 문서가 가운데면 양쪽 노트로 선이 가고, 떨어진 같은 색 칸에는 선이 없다. 떨어진 문서의 카드는 이미 있는 「→ 문서 이름 p.N」 칩(`farSource`, 이웃한 같은 색 문서 칸이 그 문서를 보이지 않을 때)이 맡는다 — 문서가 어디에도 안 보일 때도 같은 칩이 신호로 그 문서를 연다.
- **하지 않은 것**: Markdown 의 글자 범위 위치 신호(`setMarkdownJumpRequest`)는 전역 요청 하나라 여러 Markdown 칸이 같은 문서를 보여도 한 칸이 받는다. 칸 이웃을 배치 트리 기하로 따로 계산하는 모듈은 만들지 않았다(DOM 사각형이 실제 칸막이 끌기 · 접힌 칸을 따라가므로) — 시험은 트리 사각형(`layoutRects`)을 화면에 놓아 같은 판정으로 가로 줄 · 세로 · 격자 · 중첩을 확인한다(`workspaceMultiPane.test.ts`).
