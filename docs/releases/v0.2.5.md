# IWAE v0.2.5

A stability release: files written by other programs or by a newer IWAE are handled safely, Markdown highlights stay put when the file changes, and the MCP server can no longer be knocked over by a bad request.

## Changed

- Markdown highlights find their sentence again after the file is edited, inside IWAE or in another editor, and they follow the file when it is moved or renamed.
- A note whose block you are typing in and that another program changes at the same time keeps both texts, and IWAE tells you so.
- A note made by a newer IWAE, or in a shape this version can't read, opens view-only with a notice instead of looking empty.
- Document sources accept only web links and local paths. Opening a path outside the vault asks first.
- Links to a PDF with `#page=N` in Markdown open that page.

## Fixed

### Saving and data safety

- A note, canvas or `.iwae` file saved with a byte order mark (for example by PowerShell or an older editor) can be saved again instead of failing with a conflict every time.
- A damaged or newer sort order, library or metadata file no longer stops the vault from opening. A damaged file is set aside and reported; a newer one is left untouched.
- Data written by a newer IWAE is kept when you save: unknown memo blocks, fields, highlights and overlays are no longer dropped, and one unexpected highlight no longer sets the whole highlights file aside.
- PDF text boxes longer than 4,000 characters are no longer cut when the vault reopens.
- Drawings and text boxes added after the PDF edit record failed to load are saved once it can be read, instead of being lost.
- Version history keeps recording after a snapshot dated in the future, for example from a clock that ran ahead.
- One unreadable conflict or trash record no longer hides the whole Recovery section.
- A newer vault index is no longer rebuilt, and file names in a different Unicode form (a vault synced from a Mac) keep their icons, colours and favourites.

### Notes and memos

- Renaming or moving a note no longer shows "another program changed the note", and typing right after a rename no longer raises a false conflict.
- Undo and redo keep working after a note is renamed or moved.
- Throwing away a draft memo or a box memo while typing no longer saves it.
- Saving another canvas in the background no longer closes the memo you are typing in.
- Escape or Ctrl+Enter while composing Korean text no longer discards the memo.

### PDFs and tools

- Merging PDFs or inserting pages no longer blanks the other documents you have open, and merging 16 or more files works.
- Extracting many pages or splitting by chapters no longer fails on long or unusual names, and one bad chapter no longer stops the split.
- PDF links whose path contains `#` or `%` open correctly.
- Escape during a region capture drag cancels it.

### Window and keyboard

- In a small window the left bar icons no longer cover the session button and the first screen tab, and splitting a zoomed pane checks the real size.
- The tab right-click menu closes with Escape, and context menus return focus to where they were opened.
- Tab no longer leaves the settings dialog.
- An empty floating pane is no longer see-through.
- Inline styles in a Markdown file can no longer draw outside its pane.

### Backups, MCP and other

- Backups keep empty folders, and restore skips file names Windows reserves (such as `nul`) instead of losing them.
- The MCP server can no longer be crashed or stalled by a malformed request, and every request now gets an answer.
- GitHub import works in vaults stored in OneDrive.
- Long Japanese and Chinese texts are translated in whole sentences.
- Folder name clashes say "folder" instead of "file", and the remaining Korean labels in English mode are translated.
