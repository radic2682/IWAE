# IWAE 설치 프로그램 설계: 겉 창 + 속 NSIS

2026-11-16 · 상태: 소유자 확인 대기

## 1. 왜 하는가

지금 사람들이 받는 `IWAE_x.y.z_x64-setup.exe`는 Tauri가 만들어 주는 NSIS 마법사입니다. 왼쪽 그림, 「다음」 단추, 회색 Windows 대화상자 틀로 되어 있습니다. 소유자는 이 틀에 묶이는 게 싫고, 설치 화면이 투박하지 않기를 바랍니다. IWAE를 처음 만나는 화면이 IWAE답게 보여야 한다는 뜻입니다.

설치에서 까다로운 일(파일 복사, 등록, 제거, 덮어쓰기, WebView2)은 지금처럼 NSIS가 맡습니다. 보이는 창만 우리가 만듭니다.

## 2. 목표, 하지 않을 것, 실패로 볼 것

**목표**
- 설치 파일을 열면 시안 A(아래 4장)의 밤하늘 창 한 장이 뜹니다. 단추는 「설치」 하나입니다.
- 앱 안에서 업데이트할 때와 「설치된 앱」에서 IWAE를 지울 때도 같은 밤하늘 창이 뜹니다.
- v0.2.6 이하 사용자는 지금 쓰는 업데이트로 새 설치 프로그램을 받아 그대로 업데이트됩니다.
- 릴리스 절차는 지금처럼 `npm run release:local -- --publish` 한 번으로 끝납니다.

**하지 않을 것**
- macOS 설치 방식 바꾸기 (macOS 빌드는 지금 없음).
- 코드 서명. SmartScreen 경고는 이번 일로 사라지지 않습니다.
- 설치 옵션 화면. 바로가기나 파일 연결을 고르는 화면은 만들지 않습니다.
- MSI 바꾸기. MSI는 회사 PC 일괄 배포용으로 지금처럼 Tauri가 만듭니다.
- 앱 자체의 동작 바꾸기. 앱 쪽 변경은 꼭 필요한 만큼만 합니다(6.4).

**실패로 볼 것 (돌아가도 실패)**
- 새 설치 프로그램을 받은 사용자가 그다음 업데이트를 못 받는 것.
- 반쯤 깔린 상태로 남는 것. 실패하면 이전 버전이 그대로 돌아가거나, 다시 시도로 끝까지 깔려야 합니다.
- Vault나 앱 설정(`%APPDATA%\dev.iwae.desktop` 등)을 건드리는 것.
- 설치 프로그램 자신의 흔적(WebView2 데이터 폴더, 임시 파일)이 남는 것.
- 「설치된 앱」에서 IWAE를 지울 수 없게 되는 것.
- CSP나 Tauri 보안 설정을 느슨하게 하는 것.

## 3. 지켜야 할 조건 (확인한 사실)

- **업데이트가 설치 파일을 실행하는 방식:** `tauri-plugin-updater` 2.9.0은 받은 파일이 PE 실행 파일이면 NSIS로 보고 그냥 실행합니다(`infer::app::is_exe`). IWAE 설정은 `installMode: "passive"`(`src-tauri/tauri.updater.conf.json`)이라 `/P /R /UPDATE /ARGS <앱 인자>` 같은 인자를 붙입니다. 실행 직후 앱은 `exit(0)`으로 꺼집니다. 그래서 우리 설치 파일은 이 인자들을 알아들어야 합니다. 정확한 인자 순서는 `~/.cargo/registry/src/*/tauri-plugin-updater-2.9.0/src/updater.rs`의 `install_inner`(674행 부근)와 `nsis_args()`를 보고 맞춥니다.
- **`latest.json`:** `scripts/write-update-manifest.mjs`는 파일 이름이 `-setup.exe`로 끝나야 받아 줍니다. 새 설치 파일도 같은 이름 `IWAE_x.y.z_x64-setup.exe`를 씁니다.
- **Tauri NSIS의 창 없는 모드 (`src-tauri/target/release/nsis/x64/installer.nsi`, 빌드 때 생성됨):**
  - `/S`면 언어 고르기 창이 뜨지 않습니다.
  - 실행 중인 IWAE는 묻지 않고 끕니다(`CheckIfAppIsRunning`).
  - 시작 메뉴 바로가기는 늘 만듭니다. 바탕화면 바로가기는 지금의 마법사에서는 끝 화면의 체크 상자(기본 꺼짐)로만 만들지만, `/S`·`/P` 처음 설치에서는 묻지 않고 만듭니다(`CreateOrUpdateDesktopShortcut`, 업데이트 때는 만들지 않음). `/NS`를 주면 둘 다 만들지 않습니다.
  - `ALLOWDOWNGRADES`가 `true`입니다.
  - WebView2는 `downloadBootstrapper` 방식이고 `/S`에서도 내려받아 설치합니다.
  - `/R`이 있으면 끝난 뒤 앱을 켭니다.
  - 매번 `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\IWAE`에 `UninstallString`을 다시 씁니다.
  - 제거 프로그램 `uninstall.exe`는 `/S`에서 앱 데이터를 지우지 않습니다.
- **설치 언어:** `src-tauri/installer/installer-hooks.nsh`가 `$INSTDIR\installer-language`에 LCID(1042 한국어, 1033 영어)를 남깁니다. 앱은 처음 켤 때 언어를 고르지 않았으면 이 값을 따릅니다. `/S`에서는 NSIS 언어가 Windows 언어로 정해지므로, 겉 창에서 고른 언어를 이 파일에 다시 써야 합니다.
- **이 PC에서 설치 시험 금지:** 이 PC에는 소유자가 쓰는 IWAE가 `%LOCALAPPDATA%\IWAE`에 설치되어 있습니다. 설치 위치를 바꿔도 등록 키(`Uninstall\IWAE`)가 같아서 덮어씁니다. 실제 설치, 업데이트, 제거 시험은 Windows VM에서만 합니다.
- **저장소 규칙:**
  - `npm run release:scan` 통과
  - 커밋은 영어로 쓰고 Claude 언급과 Co-Authored-By를 넣지 않음, 경로를 지정해 커밋
  - push와 릴리스는 소유자 확인 뒤에만
  - 서명 키 값은 출력하지 않음
  - 화면 문구는 IWAE 문구 규칙을 따름(합니다체, 짧게, 「버전」, 대시 연결 없음)

## 4. 고려한 방식

| 방식 | 내용 | 득실 |
|---|---|---|
| **겉 창 + 속 NSIS (채택)** | Tauri로 만든 작은 설치 앱 안에 지금의 NSIS 설치 파일을 넣고, 뒤에서 `/S`로 돌린다. | 화면은 시안 그대로 나오고, 까다로운 설치 일은 시험된 NSIS가 계속 한다. 진행률을 NSIS가 알려 주지 않아 직접 계산해야 하고, 파일이 4MB쯤 커진다. |
| 처음부터 직접 만든 설치 앱 | Rust가 복사, 등록, 제거, 업데이트를 모두 직접 한다. | NSIS에서 완전히 벗어나지만, NSIS가 해 주던 일을 모두 새로 만들고 시험해야 한다. 업데이트가 끊길 위험이 가장 크다. |
| NSIS 화면만 꾸미기 | NSIS 템플릿과 플러그인으로 창을 다시 그린다. | NSIS 틀에 묶이기 싫다는 이유와 맞지 않고, 그라데이션이나 움직임을 만들기 어렵다. |
| Rust GUI(egui 등) 겉 창 | WebView2 없이 그린다. | 한글 글꼴을 통째로 넣어야 하고, IWAE와 모양을 맞추기 어렵다. |

소유자가 고른 것은 겉 창 + 속 NSIS입니다. 시안은 A(한 장짜리 밤하늘)입니다.

## 6. 동작

### 6.1 실행 모드 (인자로 정함)

| 인자 | 모드 |
|---|---|
| 없음 | 설치. 처음 화면부터. |
| `/UPDATE` 포함 (업데이트가 `/P /R /UPDATE /ARGS …`로 실행) | 업데이트. 설치 중 화면부터. 끝나면 `/ARGS` 뒤의 인자로 앱을 켠다. |
| `/S` 포함, `/UPDATE` 없음 | 조용한 설치(관리자나 스크립트용). 창 없이 6.2의 1~6단계를 그대로 한다(`/D=`는 넘겨줌). 언어는 기존 `installer-language`가 있으면 그 값, 없으면 Windows 언어. 종료 코드는 속 NSIS의 종료 코드, 뒷정리에서 실패하면 0이 아닌 값. (작성자 결정) |
| `--uninstall` | 지우기 모드 (6.3). |

### 6.2 설치와 업데이트 흐름

1. **WebView2 확인 (창을 만들기 전):**
   - EdgeUpdate의 WebView2 Runtime 등록(`{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}`의 `pv`, HKLM·HKCU, WOW6432Node 포함)으로 확인합니다.
   - 없으면 밤하늘 창을 띄우지 않고 속 NSIS를 `/P`(업데이트면 `/P /UPDATE`)로 실행합니다. 그러면 NSIS가 작은 진행 창을 띄우고 WebView2와 IWAE를 함께 설치합니다.
   - 끝나면 6.2의 6단계(바탕화면 바로가기 정리, 언어 기록, 제거 연결)를 하고 마칩니다. 드문 경우라 보기 좋지 않아도 받아들입니다.
   - MSI로 설치된 IWAE(Program Files, WiX 등록)가 있을 때도 같은 방식으로 속 NSIS를 `/P`(업데이트면 `/P /UPDATE`)로 실행합니다. 지금의 NSIS가 이 경우 MSI 설치본을 지우고(UAC 확인) 사용자 설치로 옮겨 주는데, 이 일은 `/S`에서는 일어나지 않기 때문입니다. (작성자 결정)
2. **속 NSIS 꺼내기:** 넣어 둔 NSIS 설치 파일을 고유한 임시 폴더에 꺼냅니다.
3. **기존 설치본 먼저 지우기 (손으로 설치할 때만):** 지금의 NSIS 마법사는 더 새 버전을 손으로 설치할 때 기존 `uninstall.exe`를 먼저 돌려 지난 버전 파일을 치웁니다. `/S`에서는 이 단계가 빠지므로 겉 창이 대신 합니다. 손으로 설치하거나 올릴 때 기존 설치가 있으면 `"<기존 위치>\uninstall.exe" /S /UPDATE _?=<기존 위치>`를 실행하고 끝날 때까지 기다립니다. `/UPDATE`라서 앱 데이터, 자동 시작, 언어 값은 남습니다. 실패하면 설치를 멈추고 실패 화면으로 갑니다. 앱 안 업데이트(업데이트 모드)에서는 이 단계를 하지 않습니다. Tauri의 NSIS도 업데이트 모드에서는 먼저 지우지 않고 바로 덮어쓰기 때문입니다. (작성자 결정, R13)
4. **NSIS 실행:**
   - 설치는 `/S`, 업데이트는 `/S /UPDATE`로 실행합니다.
   - 위치를 바꿨으면 마지막 인자로 `/D=<경로>`를 붙입니다(NSIS 규칙상 따옴표 없이 맨 끝).
   - `/R`은 주지 않습니다. 앱은 겉 창이 켭니다.
   - 업데이트 모드에서는 실행하기 전에 IWAE(`app.exe`)가 꺼질 때까지 최대 10초 기다립니다(업데이트는 앱을 끄고 설치 파일을 실행하므로). 그래도 켜져 있으면 NSIS가 끕니다(지금 동작).
   - 손으로 설치하거나 지울 때 IWAE가 켜져 있으면 먼저 묻습니다(소유자 결정). 「설치」·「지우기」를 누른 순간 현재 사용자의 `app.exe`가 돌고 있으면 「IWAE 켜짐」 화면(5장)을 보여 줍니다.
     - 「닫고 설치」·「닫고 지우기」를 누르면 IWAE 창에 닫기 요청(WM_CLOSE)을 보내 앱이 스스로 저장하고 닫히게 합니다. 최대 15초 기다립니다.
     - 닫히면 그대로 이어서 진행합니다. 닫히지 않으면 「IWAE가 닫히지 않았습니다」 / IWAE didn't close와 「강제로 닫기」 / Force close, 「취소」 / Cancel을 보여 줍니다.
     - 그동안 사용자가 IWAE를 직접 닫으면 화면이 저절로 다음으로 넘어갑니다.
5. **진행률:**
   - 빌드할 때 NSIS가 설치하는 파일 목록과 크기를 기록해 둡니다.
   - 설치 폴더에서 그 파일들이 쓰인 바이트로 진행률을 계산합니다.
   - NSIS가 끝나기 전에는 95%에서 멈추고, 종료 코드 0을 받으면 100%가 됩니다.
   - 막대는 부드럽게 따라가게 합니다.
6. **끝난 뒤 (종료 코드 0):**
   - 바탕화면 바로가기는 지금 기본값처럼 만들지 않습니다. NSIS 실행 전에 `%USERPROFILE%\Desktop\IWAE.lnk`(실제 바탕화면 경로)가 없었는데 실행 뒤 생겼으면 지웁니다. 원래 있던 것은 그대로 둡니다. (작성자 결정)
   - `installer-language`에 고른 언어의 LCID를 씁니다.
   - 제거 프로그램 연결(6.3)을 다시 씁니다.
   - 임시 폴더를 지웁니다.
7. **설치 끝:** 「IWAE 열기」를 누르면 현재 사용자 권한으로 앱을 켜고 창을 닫습니다. ✕로 닫으면 앱을 켜지 않습니다.
8. **업데이트 끝:** 창을 닫고 `/ARGS` 뒤의 인자로 앱을 켭니다.
9. **실패 (0이 아닌 종료 코드, 시간 초과, 꺼내기 실패):**
   - 실패 화면을 보여 주고, 기록 파일(`%TEMP%\IWAE-setup-<시각>.log`)에 원인을 남깁니다.
   - NSIS는 기존 파일을 덮어쓰다 실패해도 이전 버전을 지우지 않으므로, 「다시 시도」는 같은 과정을 처음부터 다시 합니다.

### 6.3 지우기

- 설치와 업데이트 때마다 `$INSTDIR\uninstall-ui.exe`를 둡니다. NSIS가 덮어쓴 `UninstallString`을 `"$INSTDIR\uninstall-ui.exe" --uninstall`로 바꾸고, `QuietUninstallString`에는 `"$INSTDIR\uninstall.exe" /S`를 씁니다.
  - `uninstall-ui.exe`는 같은 겉 창 코드로 만들되, 속 NSIS를 넣지 않은 작은 실행 파일입니다.
- 「지우기」를 누르면 순서는 이렇습니다.
  1. 자기 자신을 임시 폴더로 복사해 그쪽에서 다시 실행합니다(설치 폴더를 비우기 위해).
  2. `uninstall.exe /S`를 실행하고 끝날 때까지 기다립니다.
  3. 남은 `uninstall-ui.exe`와 빈 설치 폴더를 지웁니다. `uninstall.exe /S`는 「앱 데이터 지우기」가 꺼져 있으면 `HKCU\Software\iwae\IWAE`(설치 위치와 `Installer Language` 값)를 남기므로, 이 키도 지우고 `HKCU\Software\iwae`가 비었으면 그것도 지웁니다. 앱 설정 폴더는 건드리지 않습니다. (작성자 결정, Strata 세션이 Tauri 2.12.4 템플릿에서 확인한 내용)
  4. 임시 복사본은 끝날 때 스스로 지워지게 합니다.
- Vault와 앱 설정은 지우지 않습니다(`uninstall.exe /S`의 지금 동작).
- 지금의 NSIS 마법사(WebView2·MSI 대비 `/P` 경로나, 옛 설치 파일로 낮은 버전을 까는 경우)는 `UninstallString`을 읽어 `<UninstallString> [/UPDATE] [/P] _?=<폴더>`로 실행하고 끝나기를 기다립니다. 그래서 `uninstall-ui.exe`는 이 인자를 받으면 창 없이, 자기 복사·재실행 없이 `uninstall.exe`에 같은 인자를 넘겨 그 자리에서 끝까지 기다렸다가 같은 종료 코드로 끝나야 합니다.
- `uninstall-ui.exe`를 실행하지 못하는 경우가 생기지 않도록, 설치가 끝날 때 그 파일이 있는지 확인한 뒤에야 `UninstallString`을 바꿉니다. 없으면 원래 `uninstall.exe`를 그대로 둡니다.

### 6.4 앱 쪽 변경

없을 것으로 봅니다. 업데이트 설정(`installMode: "passive"`)과 업데이트 코드(`src/bridge/updater.ts`)는 그대로 둡니다. 만들다가 바꿔야 할 게 나오면 소유자에게 먼저 알립니다.

### 6.5 설치 프로그램 자신의 흔적

- 겉 창의 Tauri identifier는 앱과 다르게 `dev.iwae.setup`으로 합니다.
- 앱 실행 파일 이름이 `app.exe`이고 NSIS는 현재 사용자의 `app.exe`를 모두 끕니다. 겉 창, `uninstall-ui.exe`, 그 임시 복사본은 절대 `app.exe`라는 이름으로 돌면 안 됩니다.
- WebView2 데이터 폴더는 임시 폴더 안에 두고, 창이 닫힌 뒤 지웁니다. WebView2 프로세스가 붙잡고 있으면 끝날 때 다시 시도합니다.
- 설치가 끝난 PC에 남는 것은 IWAE 설치 폴더와 등록 정보, 기록 파일뿐입니다.
- 겉 창은 자기 CSP를 엄격하게 둡니다(외부 연결 없음).

## 7. 빌드와 릴리스

- 겉 창은 저장소 안에 별도 Tauri 앱으로 둡니다. 위치와 화면 도구는 만드는 쪽이 정합니다(9장).
- `npm run release:build`의 순서는 이렇습니다.
  1. 지금처럼 `tauri build`로 앱, NSIS, MSI, 서명을 만듭니다.
  2. 겉 창을 빌드하면서 방금 만든 NSIS 설치 파일과 파일 목록·크기 정보를 넣습니다.
  3. `IWAE_x.y.z_x64-setup.exe`를 만듭니다.
  4. 지금 업데이트 키로 `.sig`를 만듭니다(`tauri signer sign`, 키는 release.env에서 이미 환경에 들어옴).
- `scripts/release-local.mjs`는 업로드할 `-setup.exe`와 `.sig`를 겉 창 결과물에서 가져옵니다. 속 NSIS 파일은 올리지 않습니다. MSI는 지금처럼 올립니다.
- 릴리스 스크립트 테스트(`npm run test:release-scripts`)를 새 경로에 맞게 고칩니다.
- 버전 올리기 목록(package.json, Cargo 등)에 겉 창의 버전이 있다면 같이 올리거나, 앱 버전을 빌드할 때 읽게 합니다.
- 이 변경이 들어가는 첫 버전은 v0.2.7입니다. 릴리스 노트는 영어로 쓰고, 설치 화면이 새로 바뀌었다는 것을 적습니다.

## 8. 시험

**Windows VM에서 (이 PC에서는 하지 않음)**
1. 깨끗한 Windows 11에서 처음 설치. 한국어와 영어 각각. 「IWAE 열기」로 켜지고 앱 언어가 고른 언어인지 확인.
2. 설치 위치를 바꿔 설치.
3. GitHub에서 v0.2.6 NSIS를 받아 설치한 뒤, 새 설치 파일을 `/P /R /UPDATE /ARGS`로 실행(업데이트가 하는 그대로). IWAE가 켜진 상태에서도 해 보기. 다시 켜지는지, Vault와 설정이 그대로인지 확인.
4. 가능하면 실제 업데이트 경로도 확인. 시험용 `latest.json`을 가리키게 빌드한 v0.2.6-test에서 앱 안의 업데이트 단추로 새 설치 파일 받기.
5. 새로 설치한 버전에서 다시 다음 버전으로 업데이트(업데이트가 끊기지 않는지).
6. 설정 → 앱 → 설치된 앱에서 IWAE 지우기. 밤하늘 창이 뜨는지, 설치 폴더와 시작 메뉴가 정리되는지, Vault와 `%APPDATA%` 설정이 남는지 확인.
7. 지운 뒤 다시 설치.
8. 설치 중 겉 창 프로세스를 강제로 끄기. 다시 실행하면 정상 설치되는지 확인.
9. `/S` 조용한 설치.
10. Windows Defender로 설치 파일 검사.

**이 PC에서 해도 되는 것**
- 겉 창 화면을 브라우저 미리보기로 띄워 상태별로 2배 화면 확인(밝은 테마는 없으므로 밤하늘 한 가지, 100%와 150% 배율).
- 설치를 실제로 하지 않는 단위 테스트(인자 해석, 진행률 계산, `UninstallString` 바꾸기 등은 가짜 경로로).

**시험하지 못할 수 있는 것:** WebView2가 없는 PC(Windows 11에는 늘 있음). 시험하지 못하면 그렇다고 보고합니다.

## 9. 만드는 쪽에 맡기는 것

- 겉 창 앱의 폴더 이름과 구조, 화면을 Vite로 만들지 정적 파일로 둘지.
- 속 NSIS를 실행 파일에 넣는 방법(컴파일 때 `include_bytes!` 또는 뒤에 붙이기)과 `uninstall-ui.exe`를 따로 빌드하는 방법.
- 별 그림 구현과 진행 막대를 부드럽게 하는 방법.
- 임시 파일과 자기 삭제의 구체적인 방법.
- 기록 파일 형식.
